# 设计与技术方案

本文档说明 Rotor Trails 的整体架构、各个系统的实现方式和五张地图的关卡设计。数值都来自代码中的集中配置（`src/config/flight.ts`、`src/sim/damage.ts`、`src/sim/buffs.ts`、`src/sim/scoring.ts` 和各地图文件），改配置即可调整手感与难度。

## 1. 架构

```
浏览器帧（requestAnimationFrame，帧率不固定）
  └─ FixedStepper：把帧间隔换算成固定 1/60 s 的物理步（单帧最多 6 步，超长帧截断）
       └─ GameSession.step()（纯仿真，不依赖 DOM，可在 Node 里运行和测试）
            天气 → 风场采样 → 近地射线 → 起落架力 → Buff 计时 → 飞行模型（力/力矩）
            → Rapier 物理推进（唯一的位置积分）→ 碰撞与损伤 → 接地/降落判定
            → 补给拾取 → 维修站 → 任务 → 导航 → 地形告警
  └─ 渲染（three.js）：按插值系数在上一步与当前步之间插值显示，与物理解耦
```

- **唯一的运动真相**：直升机的位置和速度只由 Rapier 刚体积分；飞行模型只输出力和力矩，渲染只读取状态。
- **固定步长**：物理结果只取决于步数，与显示器刷新率无关（测试覆盖 30/60/144 FPS 与抖动帧）。切后台、卡顿后的超长帧被截断，不会一次补算导致“瞬移”。
- **暂停**：暂停时不推进仿真，Buff、阵风、天气等所有计时都基于仿真时间，因此一起冻结。页面切到后台自动暂停。
- **模块化、配置驱动**：地图是数据（地形函数、站点、航点、航段、任务、天气、风区、道具），新增地图不需要改引擎代码。

## 2. 飞行模型（`src/sim/flight.ts`）

参考一架约 1750 kg 的轻型单旋翼直升机（旋翼半径 5.3 m）：

- **旋翼推力与功率**：动量理论诱导功率 + 型阻功率 + 爬升功率；可用功率 = min(传动限制 340 kW, 发动机 470 kW × σ^0.7) × 耐久性能系数 × (1 + 动力增强)。σ 为空气密度比（随海拔指数下降，每升高 1000 m 约降 11%）。
- **桨叶失速限制**：总距满行程时的推力 = 2.2 × 基础重量 × σ，并保底不低于当前重量的 1.12 倍——任何海拔、任何载重下都不会出现“无法起飞/无法脱离”的死局。海平面和高原上都先受功率限制。
- **惯性与气动**：机身三方向阻力面积、桨盘 H 力（低速时更大）、升降阻尼、平移升力（ETL）、地面效应、桨盘后倒与上反效应、风标效应、主旋翼反扭矩与尾桨。
- **风通过相对气流作用**：所有气动力都用“机体速度 − 风速”计算，风不会被辅助系统抵消掉。
- **起落架**：四个滑橇支点的射线弹簧-阻尼模型，带静摩擦，可以稳定停在坡面上。

### 三档辅助（`ASSISTS`）

| | 新手 | 标准（推荐） | 挑战 |
| --- | --- | --- | --- |
| 姿态 | 松杆自动改平并缓慢减速 | 松杆改平，保留惯性 | 角速度控制，松杆保持当前姿态 |
| 垂直 | 保持高度，近地自动限制下降速度 | 保持垂直速度，近地限制下降速度 | 总距直接控制升力 |
| 反扭矩 | 完全协调 | 完全协调 | 不完全协调 |

- **悬停辅助（H）**：逐渐减速（不是瞬间锁定），低速时用积分项抵消持续风，速度足够低后保持位置；滑橇触地后自动关闭。**默认关闭**：休闲飞行起飞、跳景点、安全恢复都不替玩家打开（恢复时按检查点那一刻玩家自己的选择）。新手辅助下 GameSession.watchHover 看玩家是不是停不稳——低空（< 70 m）低速（< 7 m/s）时松开前后左右键、被推出起点 12 米以上，或者 12 秒内前后左右换向 5 次，累计 3 秒就发 hoverHint，界面提示按 H；每次飞行最多 3 次、间隔 90 秒，玩家自己开过一次就不再提示，教学、自动巡航和回放里不提示。
- **下降限制**：离地越近允许的下降速度越小；按约 0.7 s 后的离地高度预判，并在动力余量小（高原）时收紧。
- **动力上限保护**：持续掉高度时自动减小前倾，把动力留给升力。
- 输入有平滑（上升/回落速率），避免键盘输入造成的突变。

## 3. 风与天气（`src/sim/wind.ts`、`src/sim/weather.ts`）

- **风场** = 基础风（方向缓慢摆动）+ 连续湍流 + 局部风区。风区为胶囊形区域，可限定高度范围，分三类：
  - `channel` 通道风：把风扭转到通道方向（峡谷顺谷风、山口下坡风）
  - `gust` 规律阵风：周期可预测，HUD 提前约 3 秒预警“阵风将至”
  - `lift` 垂直气流：上升/下沉气流（迎风坡、背风坡、峭壁）
- **天气**：晴、小雨、暴雨、浓雾、低云、大风等参数组合（风、阵风、湍流、云量、阴天、雨、能见度、低云层高度、闪电、地面湿润），天气之间平滑过渡；“动态天气”会在完成某个任务后转变（例如雨林的晴转暴雨）。
- **风的可见线索**：风向袋（`src/render/windsock.ts`：五节橙白软布，喉口钢圈挂在 V 形支架上；鼓起来的长度按风速走，约每节 3 节风速，7.7 m/s 以上整条吹平，后面没鼓起来的部分压扁往下坠，风大时尾巴左右甩；形变在 CPU 上算，700 米外隔 20 帧算一次）、旗帜、经幡、树木摆动、雨线倾斜、风声；HUD 显示风速、来向、阵风和当前风区名称。
- **场景里的导航**：世界里只放现实中说得通的东西——任务目标是烟幕和闪烁的引导灯，补给是悬停的无人机，方向与距离看 HUD 的目标菱形和屏幕边缘箭头；三维光环与箭头是可选项（设置 → 三维航线标记，默认关）。
- **雾和云中的公平性**：HUD 标记不受雾影响；打开三维航线标记时，航点光环、航线箭头不受雾影响（仍会被地形遮挡），信标灯光可穿透雾气；HUD 的航点方向/距离、转弯预告和地形告警始终有效。

## 4. 碰撞与损伤（`src/sim/damage.ts`）

- **耐久 0–100**：70 以上正常；70–30 受损，性能与稳定性逐渐下降；30 以下严重受损，性能明显下降但始终保留控制能力；0 为坠毁。性能系数 = 1 − 0.28 × (1 − d)^1.6，连续变化、没有台阶。
- **按冲量结算**：Rapier 接触力 × 步长 → 冲量 → 速度变化。同一部件 0.45 s 内的接触合并为一次碰撞，按累计速度变化减去容差计算伤害——持续顶着障碍物不会每帧重复扣血。
- **旋翼/尾桨撞击**单独计算并有冷却时间；贴着障碍物高速滑动会持续擦碰伤害。
- **接地**：下降速度、水平速度、姿态超过安全值才扣耐久；轻微重着陆（伤害 < 3）不计入碰撞次数；水平速度很大时归类为“机身撞击”。
- **致命事件**：侧翻、落水（不属于普通碰撞，护盾也挡不住）。
- **撞得上的东西**：地形、水面、程序几何体（`solid` 不是 false 的图元）、树；只放了 Blender 模型、中间没生成碰撞体的道具在 `PropBuilder.endModel` 里用模型自己的碰撞箱（`src/world/modelShapes.ts`，由 `tools/blender/collision_shapes.py` 把模型体素化、填实、贪心拼成几个盒子：渡轮 10 个，小飞机 8 个，路灯 3 个）；细杆子（风向袋、旗杆、路灯杆、船桅、塔顶相轮、木桩）是实心的细圆柱。
- **会动的东西**（`src/sim/movers.ts`）：船、路上的车、绕场的小飞机，位置和朝向只由时间决定（`pose(t)`）。世界生成时建好（`WorldData.movers`），物理里是运动学刚体（每步给下一步结束时的位置，撞上去它不让开），画面用同一个钟（飞行中是模拟时间）摆模型，存档、回检查点不用记它们在哪。小飞机下雨起雾不飞，碰撞箱跟着关掉。
- **维修**：绿色维修坪停稳 4 秒恢复（有使用次数），或拾取维修补给 +25；性能随耐久恢复。

## 5. Buff（`src/sim/buffs.ts`）

| Buff | 规则 |
| --- | --- |
| 动力增强（黄色闪电） | 拾取后储存 1 次（持有时不能再拾取，补给留在原处），按 C 使用；7 秒内可用功率 +25%、爬升上限提高；0.6 s 渐入、1.5 s 渐出 |
| 免伤护盾（蓝色六边形） | 拾取即生效 9 秒；挡住耐久损失，但碰撞照常发生（会被弹开、计入碰撞次数）；重复拾取最多延长到 14 秒 |
| 维修补给（绿色十字） | 立即恢复 25 耐久，不超过 100；耐久满时不被消耗 |

所有补给只能拾取一次；检查点保存/恢复完整的 Buff 状态与已拾取记录，不能通过反复读档刷补给。

## 6. 任务、检查点与评分

- **任务类型**：`land` 降落（停稳后停留数秒卸货/接人）、`hover` 悬停投放（在指定高度区间稳定悬停）、`inspect` 巡查（按顺序低速飞过若干点，可带引导航线）。
- **降落判定**：下降速度 ≤ 2.5 m/s、水平漂移 ≤ 2.5 m/s、姿态 ≤ 12°、落在坪内；右下角着陆辅助实时显示四项是否满足，停机坪被机头挡住时也能用。
- **检查点**：起点、每完成一个主线任务、经过标记的航点时自动保存（位置、姿态、速度、耐久、任务进度、Buff、已拾取补给、天气）。失败后可以：从最近检查点继续、从更早的安全检查点继续、安全恢复（以稳定悬停状态继续，耐久至少 40，计入评分扣分）、或从关卡起点重来。
- **评分（不使用时间）**：主线 600 + 每个可选任务 120 + 剩余耐久 ×2 − 每次碰撞 15（最多扣 180）+ 最终降落质量（最多 200）− 每次安全恢复 60。S ≥ 1050，A ≥ 900，B ≥ 760，C ≥ 620。用时只记录、不计分。

## 7. 导航（`src/sim/nav.ts`）

- 每个航段由一条或多条路线组成；分岔处同时显示各路线的说明、距离和方位，飞向其中任意一条即自动选定（按 N 切换推荐）。
- 三维航点：光环、沿航线的少量箭头；高速时转弯预告提前（预告距离 = max(350 m, 速度 × 14 s)），给出建议速度和高度。
- 偏离航线时给出恢复引导（先爬升到安全高度，再飞向最近的航点）。
- **航线净空检查**（`src/sim/routeCheck.ts`）：沿每条路线检查与地形、水面、建筑（含悬空结构，例如岩拱）、树冠的净空；`autoAlt` 航点在生成地形后按实际障碍自动抬高；`npm run mapviz` 输出俯视图和问题清单，测试要求每张地图 0 问题。

## 8. 世界生成与渲染

- **地形**：每张地图用数学函数（噪声、山脊噪声、样条距离场）生成高度场，再用样条“刻”出河道、峡谷、峡湾、冰川谷，整平站点；同一份高度场同时用于 Rapier 碰撞（已用测试验证三角剖分一致）和渲染。地表遮罩（沙、泥土/道路、无树区、积雪）由生成过程绘制。
- **地形着色**：坡度/高度/遮罩混合草地、岩石、积雪、沙滩，岩层条带（峡谷）、湿润、森林地面；中高画质使用 Poly Haven 照片材质（每张地图 8 层，打包成纹理数组）：平地用俯视投影（近处 + 旋转后的大尺度两次采样打破重复），陡坡逐渐改用三平面投影，照片颜色按亮度保留明暗、色相向地图的生物群系颜色靠拢；积雪按带细节的法线判断朝上程度（雪积在岩石平台与凹处）。低画质退回程序着色。
- **建筑与道具**：道具函数用程序几何体生成碰撞体和后备外观；有 Blender 模型的建筑在 `beginModel / endModel` 之间登记模型实例（位置、朝向、按本栋尺寸缩放），渲染时跳过对应的程序几何体，模型按材质合批画（`PropBatches`，`src/render/modelLib.ts`、`propsView.ts`）：同一种材质、同样投不投影、同样进不进最近两层阴影的子网格不管属于哪个模型，都放进一个 `BatchedMesh` 一次提交。以前每个模型的每个子网格一个实例化网格，日本港口一屏两百多个，three.js 每提交一个物体有十几微秒的固定开销，主线程每帧光这些就要四五毫秒；合批后几十个，停机坪 69 → 85 帧。三级细节模型按距离切换（每个实例只有一级可见，10% 滞后），可见集合只在换级时重排；不做逐个实例的视锥剔除（以前每个实例化网格的包围球也盖着整张图的同类实例，本来就剔不掉）。模型由 `tools/blender/props_<地图>.py` 生成，参照照片建模、使用照片材质，子网格按材质合并。碰撞体为盒、圆柱、球、胶囊。动态对象（风向袋、旗帜、经幡、信标灯、闪烁灯）由锚点生成。
- **植被**：按密度、坡度、高度和遮罩散布，实例化渲染；只为直升机附近约 85 m 内的树创建碰撞代理。10 个树种由 `tools/blender/trees.py` 生成三级细节（近景：弯曲渐细的枝干、板根、侧枝和伸进叶子里的细枝 + 法线朝外的叶簇卡片；中景：简化；远景：体块树冠）。叶片图集（4096，每格 1024）是照片：本机 MOSS-Image 生成白底的小枝照片（常绿橡树、黑松、云杉、热带阔叶、白桦、刺柏、冬青、椰子叶、矮松、犹他刺柏、山艾），`tools/blender/leaf_photo_atlas.py` 抠掉白底、去白边，十几根缩小的小枝随意散成一团（不围成整齐的一圈，否则每张叶卡都是一朵一样的花），照片里棚灯打出来的反光和发白的叶脉压回叶面平均亮度附近（游戏里还会再打一次高光，不压的话雨林泛银白色），每格的平均颜色和疏密（叶子挡住的面积占几成，只许密一成）都对齐原来程序画的那一格：各地图调好的树色不变，照片叶簇比程序画的实，不对齐的话树冠没了缝、透不过光，大峡谷的矮松、刺柏成了一团团黑球。灌木是一大四小几团枝叶高高低低挤在一起、底下贴地，最细一级有从根上长出来的枝（以前是一个椭球，换了照片叶子像一颗颗包菜）。叶片用 alpha 测试，远处按 mip 级别补不透明度避免变稀。
- **树的风摆**（`treeView.ts` 的 `windPosition`）：加载模型时给每个顶点算风参数 `aWind`（相对高度、枝的相位、离树干多远、树高，同一种树三级细节一套）。整棵树像悬臂梁一样弯（挠度约和相对高度的平方成正比，树高 H 的树梢最多挪 0.1·H^0.75 × 风的幅度），弯的时候树梢往下沉、长度不变；摆动频率是固有频率（10 米高约 0.55 Hz，越高越慢，灌木快）；树冠外沿的枝条按自己的相位摆，比树干快；叶子 2~4 Hz 小幅抖动；阵风一团团扫过去。旋翼下洗把树冠压弯，最多约 1.8 米（以前能推出四五米），里面的枝叶乱抖。
- **光照与大气**：Preetham 物理天空（太阳盘、云层银边），环境光照由天空预滤波得到；雾按高度衰减，朝太阳方向带阳光的散射色，云中另有雾浓度。阳光阴影使用四级分层阴影（分界 4 / 40 / 320 / 2600 m），每个受光材质都通过同一个钩子接入阴影与雾（`sunShadows.ts`、`atmosphere.ts`）。
- **水面**：8 组解析波浪（按像素覆盖范围淡出，避免远处摩尔纹）+ 噪声细节；岸边白沫来自水深纹理；亚马孙河为浑浊模式；粗糙度随距离增大。
- **岩层**（`src/world/rockForm.ts`）：峡谷、峡湾、喜马拉雅的地图配了一张地层表（每层的厚度、硬度、颜色）。在雨水侵蚀之后把陡坡改成“硬层成崖、软层成坡”的剖面；地层面可以倾斜、缓缓起伏（几个正弦波相加，CPU 和着色器算出来的值完全一样）。颜色在地形着色器里按同一张表（`strataLUT`，一行 4096 像素的贴图，含纹层和接触线）查，所以层线和台阶对得上，绕山一圈连续。岩壁在水平方向再扭一扭（`warp`，出现支墩和凹龛），太陡的地方先崩塌（`talus`）。岩拱、石林这些岩石道具用同一张表。侵蚀里陡坡上只有“软弱带”冲得出沟，细沟再抹掉，避免满山窗帘褶。
- **山影**（`src/render/sunMap.ts`）：加载地图时沿太阳方向扫一遍高度场，得到每个位置头顶上“被山挡住的光线到了多高”，存成一张半精度贴图。方向光的颜色节点乘上它，所以地面、水面、树、建筑、座舱和体积雾都有山的影子，而且是三维的（飞到影子上面就回到阳光里）。分层阴影的最远一层不再画地形：那一层里只有镜头附近的地形块投影，影子落到远处山坡上是一条条直线。背阴的地形按“对面晒着太阳的岩壁把光反射过来”加一点暖色的自发光（`terrainShader.ts` 末尾），峡谷的清晨黄昏靠它。
- **人眼适应**（`src/render/eyeAdapt.ts`）：把色调映射之前的画面缩成 64 格，异步读回各格亮度（不让 CPU 等 GPU），按中央权重算平均亮度，曝光按时间常数靠向目标（变亮 2.6 秒、变暗 1.1 秒）。只补偿一部分，黄昏还是黄昏；转头看后舱时画面慢慢提亮。
- **水面倒影**（`src/render/mirror.ts`）：沿反射方向走三段。先在屏幕上步进 17 步 + 二分 3 次，碰到画面里的东西就取那里的颜色；飞出画面的光线接着在**倒影场**（`src/render/reflectMap.ts`：地形 + 树冠的高度图和俯视颜色图，打光在着色器里算）里走 20 步，所以山在画面外时水里还是映得出来；什么都没碰到就是天空，按方向算大气颜色（`SkyDome.reflectedSky`），再盖上云层贴图里的云。天空不从画面里取：座舱立柱、山挡住的方向一样有天。远处的倒影按“比像素还细的波”上下拉开（三点采样 + 每像素抖动）。海面和河面共用，低画质关闭。
- **太阳碎金**（`water.ts` 的 `WaterLighting`）：水面的方向光高光换成统计模型：算出把太阳反射进眼睛的小波面要多大坡度，和画得出来的波浪比，比像素还细的部分按 Cox-Munk 的坡度分布算概率。近处是一粒粒闪光，远处自然连成一条光带；`lightColor` 里已经乘过各种影子，影子里没有碎金。月光走同一条路。
- **水面远近一个样**（2026-11-08）：海面坡度的方差按 Cox-Munk 定总量（每个方向 `s2`），分给画出来的 8 组浪、两层滚动噪声细纹（幅度 0.5、0.35 × √s2，噪声的 uv 坡度均方根约 10，先除掉）、闪烁的小波和比像素还细的部分；哪一层因为像素盖住的尺寸变大而淡出（细纹按 0.05~0.45 米、0.02~0.16 米的像素尺寸，浪按波长的 5%~20%），它那份方差就挪进碎金的统计宽度和反射的粗糙度。以前细纹直接乘 0.9、0.45，近处坡度均方根 0.25~0.4（比真实海面粗两三倍），过了 60~700 米硬性淡出，低空看得到“细纹到这里为止”的一圈。碎金另加一层颗粒（两层白噪声相乘再三次方，按贴图本身算的均值归一化，最清楚的一级贴图采样，像素 0.12~1.4 米淡出）：近处一粒粒很亮的闪光中间露出暗的水，远处平均成光带，平均亮度不变；浪群的起伏从 0~1.7 倍收到 0.55~1.45 倍，逆光不再是一团团棉花似的白斑。
- **白浪**（`water.ts` 的 `whitecapCover`、`capThresholds`）：风大了浪头破碎。覆盖海面的比例按 Monahan & O'Muircheartaigh（1980）W = 3.84×10⁻⁶·U^3.41（4 m/s 几乎没有，9 m/s 约 0.7%，14 m/s 约 3%，封顶 20%）；白浪场是噪声贴图 r、g 两个通道顺着风拉长（2.5 倍）、往下风方向移动，门槛取白浪场分布的 1 − 覆盖比例分位数（加载时按贴图本身算一张表，每帧按风速插值）；像素盖住 0.35~1.3 米以后换成按覆盖比例算的平均亮度。浑水河不起白浪。
- **岩壁细节**：岩石浮雕图（`tools/prep_relief.py`）不是程序噪声，是把真实悬崖（Poly Haven `cliff_side`）的法线积分成高度，放大到 19 / 71 / 230 米三个尺度；三平面投影时 v 轴取“地层坐标”（高度 + 地层面偏移），岩层跟着地层表倾斜、起伏，贴图的上下也摆正了。A 通道是凹处，裂缝和岩层下沿压暗；再加一层顺岩壁流下来的水痕。
- **水系**（`src/world/flow.ts`）：优先填洼后累加集水面积（半分辨率），存进森林图的 G 通道（地形着色器的贴图数已到 WebGPU 默认上限 16）。荒漠里沟是一条条浅色的干河道（`biome.wash`），别处沟里植被更密更绿；植被规则的 `wash` 让灌木沿沟生长。
- **河流**（`src/world/river.ts`、`src/render/riverView.ts`）：地图的 `rivers` 给出沿下游方向的点（水面高度、半宽），`riverLine` 沿谷底中心线蜿蜒并绕开停机坪。地形挖出河床、把两岸修到水面高度；水面是一条带子，两边埋在河岸下面。急流处按坡度起白沫。不参与飞行模拟。
- **旋翼下洗**（`src/render/downwash.ts`，水面部分在 `water.ts`）：桨毂离地面约 26 m 以内开始起效，水面上是一圈向外跑的碎浪和白沫，加上一圈水雾；陆地上是尘土（水泥坪几乎没有），积雪线以上是雪沫。只影响画面。
- **草丛**（`src/render/groundCover.ts`）：贴地 75 m 以内在镜头周围铺草丛（16 m 一块，环形缓冲区，只上传变化的部分）；颜色用和地形草地层相同的噪声与配色，远处淡出。飞高了整组隐藏。
- **窗灯**（`src/render/wetness.ts` 的 `windowGlow`）：黄昏全开、清晨和阴雨天亮一部分，按世界坐标约 2.6 米一格抽签，大约一半的窗户亮着。建筑模型里“又暗又光滑”的纯色部件和程序建筑的玻璃都算窗。
- **石块**（`boulder`）：走树木的实例化和 LOD，不参与碰撞，撒在崖脚、岩架、冰碛和岬角下；颜色是地图的岩石色去一半饱和度。
- **锐化**（`post.ts` 的 `sharpen`）：时间抗锯齿之后一道受限的反锐化，结果限制在周围五个像素的明暗范围内，不产生白边。
- **低云层**：开体积雾时在 `volumetricFog.ts` 里沿视线与云层相交的一段积分（按场景深度截断，云贴着山坡自然消失）；低画质或关掉体积雾时退回 `CloudLayer` 的半透明面片。
- **飞行中的流畅度**：`render/instancing.ts` 让实例网格不走 three.js 的“上一帧矩阵”（否则每帧复制整张矩阵表，矩阵一变还要整块重传；树、石块、建筑本来就不动，上一帧位置直接取当前位置）。`treeView.ts` 的列表是增量维护的：每棵树记着自己在哪一级、哪个槽位，刷新时只改换了细节级或进出视野的树，一帧最多挪 2000 棵远处的树，其余排到后面几帧。整张列表重写一次要传几 MB，传输队列一满，后面几十字节的写入也要排队。
- **地平线**：`FOG.ring` 是地平线一圈 7 个颜色（`SkyDome` 按穹顶同样的公式算），雾、远云都融进视线方向的这圈颜色，远景后面正好就是这个天色；`water.ts` 里像素覆盖范围带来的坡度方差要封顶，否则几十公里外的海面朝哪个方向都反光。
- **任务烟幕**（`render/smokePlume.ts`）：一次实例绘制的烟团，同一时刻放出的摆动同相，连起来是烟柱；每团放出来时按当时的风定下升多快、散多开（升速 ×1/(1+u/10)，烟团放大 1+0.04u，风大时少丢团、每团浓一点），没风是直柱，9 m/s 的风里斜着拖出去，和真的信号烟一样看得出风向；橙色飘远了变成偏暖的淡灰；按半球法线受光，用场景深度做软边，镜头靠近时淡出。水面、河流、烟幕共用一份场景深度拷贝。
- **飞行界面**：默认“自动”：平稳飞行 6 秒后面板和按键提示都收起，只留没有底色的航向带和下一个航点；有告警、分岔、着陆、任务变化、低速时回来。按 U 切换 自动 / 完整 / 隐藏。
- **飞行训练**（`src/game/tutorial.ts`）：`LESSONS` 里 7 课 26 步，每步写清楚做什么、为什么、放大显示哪些键、看 HUD 的哪里；`check` 读真实飞行状态，`stuck` 是卡住 14 秒后的针对性提示。没学到的操作在 `filter` 里置零，HUD 用 `Hud.setTutorial` 只露出学到的部分。`anchor` 步骤开始时存一个不打扰的检查点，撞了回到这里、耐久补满。可以从任何一课开始（`Lesson.place` 把飞机放好）。
- **休闲飞行**（`RunConfig.free`、`GameSession.free`）：没有任务、补给、检查点和导航，磕碰慢慢恢复，撞毁就回到上空。起点是第一个观景点（`MapDef.vistas`）。暂停菜单换时段、天气、景点（进出夜晚要多一盏着陆灯，所有材质重新编译，所以等 `warmUp`）。`src/sim/cruise.ts` 的自动巡航只通过操纵输入飞，看前方 720 m 的地形，前面有山就减速先爬。电影镜头（`CameraRig` 的 `cinema` 模式）在飞越、伴飞、高空之间切，被山挡住就换下一个。
- **第一印象**：训练场是主菜单的背景，也是第一个看到的世界，按正式地图的标准做（`src/maps/training.ts`、`src/world/props/training.ts`、`tools/blender/props_training.py`）。菜单先放 `public/ui/map_training_bg.webp`，`App.warmMenu` 在后台并行编译，好了再淡入实时画面。`public/ui/` 的图都是游戏里拍的（960×400 卡片、1280×720 加载背景）。
- **并行编译**：`WorldView.parallelCompile` 在预热期间让新建的管线走异步接口（同步接口在显卡进程里只能排队），没编译好的物体先不画；生成世界之前 `WorldView.prefetch` 先把模型和贴图下载起来。
- **着色器编译**：WebGPU 的渲染管线第一次用到时才编译（地形着色器 140 KB，一次要好几秒），所以 `App.warmUp` 在加载界面里让 `WorldView.setWarm` 把场景所有物体都画一遍（隐藏的也画、不做视锥剔除），等帧时间稳定后才进入“点击开始”。环境贴图重烘时写回同一张贴图，否则所有材质都要重新编译。地形颜色不放在 `colorNode` 上：three.js 会把 `colorNode.a` 带进阴影通道的着色器。
- **座舱与直升机**：驾驶舱对照 H125 实机照片建模（`tools/blender/cockpit.py`，烘焙环境光遮蔽），指针按仪表读数转动，发动机/地图/姿态屏为实时绘制的画布贴图；外观（机身、旋翼、尾梁、滑橇）由 `heli_ext.py` 生成，旋翼按转速变成半透明的桨盘。
- **机身涂装**（`src/render/heliLivery.ts`、`tools/blender/heli_livery.py`）：不走 UV，机身坐标直接投影到一张 4096×3200 的图上，左舷、右舷、俯视各一块，朝上朝下的面用俯视那块，朝下的再染成机腹的深蓝。这样分色线和网格的面没有关系：以前按面分配材质，尾部的条纹是一排锯齿。座舱外壳和后机身是两个模型，用同一张图、同一套投影，接口自然对得上。接缝、铆钉在高度通道里，清漆上有一点起伏。右舷的 u 是反的：贴图里都是人站在飞机旁边看到的样子，文字不会反。
- **手柄**（`src/game/gamepad.ts`、`src/ui/padNav.ts`）：`Input.axis` 键盘优先，键盘没按就用手柄的模拟量，所以飞行、拍照的机位、教学判断“按住了没有”都不用改。每帧读一次（`pollPad`）。菜单都是网页元素，`padNavigate` 按屏幕位置找这个方向最近的控件，滑块左右调值，有弹窗只看弹窗。从手柄开始飞的话浏览器不给鼠标锁定（不算用户手势），这时不提示。撞击走 `App.shake`：镜头和手柄一起震。超仿真的开关还是要用鼠标。
- **拍照模式**（`src/game/app.ts` 的 `openPhoto`、`cameraRig.ts` 的 `movePhoto`、`src/ui/photoPanel.ts`）：状态还是暂停，世界定格，只走机位。鼠标不锁定，按住才转镜头，放开了能点面板。速度按离地高度定，朝前走跟着镜头的俯仰，长焦的时候转得慢。桨叶默认定住（`HeliModel.frozen`，相当于快门很快），勾“旋翼虚化”才是虚的。虚化用超仿真那一步景深（`post.ts`），模糊圈上限放大三倍，采样点从 22 个加到 48 个，动了滑块才重建后期；有直升机就对直升机，藏起来了就对画面中间的地面。
- **地图外面的林子**（`MapDef.fringe`、`farCanopy`，`vegetation.ts`、`terrainShader.ts`）：亚马孙的远景地形抬到了树冠的高度，只有一层贴图。起飞点离地图边 400 米，一抬头就是一块绿布。现在地图外面再种一圈真树（只种高的，单独的随机数，地图里面的树一棵不变），种在抬高之前的地面上，树冠才是从林冠层里鼓出来的。那一圈里地形这一层是树冠中间的缝，要比树冠暗（`gapOut`），真树画不到的距离上不再压暗，不然飞高了地图外面有一圈黑边。林冠层本身也暗了一些，多了几十米和几百米尺度的明暗（`clump`、`patch`）：实测同一距离下比真树亮 20%，方差只有三分之一。
- **云的形状和明暗**（`sky.ts` 的 `cloudDensity`、`volumetricClouds`）：以前高度轮廓收得太早，一朵云是压扁的一张饼，从海上看全是横着的。现在中段鼓起来，到顶才收（`prof`），三维噪声不再竖着压扁；云底朝下，看到的是地面不是天，环境光压到一半，一朵云才有底，才是立着的。云底的亮主要靠多次散射：小积云的光学厚度只有十几到几十，阳光有三四成能从云底透出来，真实照片里云底是浅灰。以前多次散射只占 0.22、迎光面靠一个后向散射瓣撑着，这部分光进不到云里，远处的云底是一条深灰的扁圆盘，从低处看像飞碟；现在后向的瓣 0.15、多次散射 0.5（二流近似 T ≈ 1 / (1 + 0.13 τ)）。云底保持平的（同一个凝结高度）：试过让云边的底往上收成圆角，下半截成了光滑的面团。体积云的渲染像素封顶 52 万（`cloudPass.ts`），大屏幕上再降一点分辨率，1080p 及以下不受影响。侵蚀只会把密度往下减：形状这一步是 0（晴空）就跳过高频噪声的采样，步进里大部分采样点在晴空里，云的显卡开销降到原来的三分之一，画面不变。
- **走的船**（`src/render/vessels.ts`，`MapDef.vessels`）：日本的渡轮和渔船、峡湾的渔船、亚马孙的客船。模型和港里停着的是同一批（`instanceModel`），不给航线就在开阔水面上自己找一个椭圆（`findLoop`，绕一圈全是够深的水，离岸留 60 米）；亚马孙沿河上去靠另一边下来。尾浪是贴在水面上的一块三角形，张角按开尔文尾迹 19.5°，白沫的噪声按世界坐标取，留在水上不跟着船跑。没有碰撞。
- **阔叶树和白桦的树冠**（`tools/blender/trees.py` 的 `lobes_of`）：以前是一根棍子顶一个球。现在主干不高就分枝，树冠是几团大小不一的枝叶叠起来的，叶卡按表面积分到每一团（按体积分的话小团只有两三张卡，飘在外面），法线一半朝这一团外面，每一团都有上亮下暗。两级细节用同一个种子，换级时轮廓不跳。白桦的树皮以前用了松树皮的材质，贴图坐标却指向图集，树干是棕色的；现在是单独的材质 `tree_bark_birch`。
- **鸟**（`src/render/birds.ts`，`MapDef.birds`）：一张图二十来只，一次绘制。位置在 CPU 上算（绕着起降场和观景点盘旋，圈子和高度慢慢变），翅膀在顶点着色器里扇。`positionNode` 跑的时候实例矩阵已经乘过了，所以翼根到翅尖的距离要看 `positionGeometry`，抬起的方向用每只鸟自己的“上”。直升机 130 米内就往外、往上让开。夜里和大雨的时候收起来。
- **飞行员**：外面的镜头（追尾、电影、拍照）都看得到，模型在飞起来之后才下载。座舱里只有超仿真有身体。从外面看时座舱的控件回到真实的机长位（`viewCenter` 只对座舱镜头生效）。
- **渲染器**：three.js WebGPURenderer（不支持 WebGPU 时自动退回其 WebGL2 后端；`?backend=webgl` 可强制），反向深度缓冲；所有自定义着色都用 TSL 节点写成（地形、水、天空、树、道具细节、座舱玻璃、天气），同一份代码可编译成 WGSL 或 GLSL。
- **后期处理**（`src/render/post.ts`）：低画质 = FXAA；中及以上 = 多渲染目标（颜色、法线、运动向量）→ GTAO 环境光遮蔽 → TRAA 时间抗锯齿 → [泛光] → Khronos PBR Neutral 色调映射 → 显示空间调色（S 曲线、自然饱和度、分离色调、暗角）；可选按运动向量的动态模糊。离镜头 2.5 m 以内（座舱内部）不叠加屏幕空间遮蔽（座舱模型已烘焙遮蔽）。
- **体积雾与丁达尔效应**（`src/render/volumetricFog.ts`，中及以上画质，设置里可关）：在 GTAO / SSGI 之后、TRAA 之前叠加。约半个屏幕分辨率沿每个像素的视线步进：近处（≤ 0.8–1.5 km，平方分布、密在近处）累加贴地薄雾（按地表高度图的离地高度衰减，林区更浓，三维噪声的团块随风飘动）与低空霾，每个采样点用 CSM 第 2~4 层阴影贴图判断阳光是否被挡住、再乘云影；Henyey-Greenstein 前向散射（g ≈ 0.72~0.76）让迎着太阳时光束最亮。远处（到 8 km）只统计视线上被遮挡的比例，按解析雾的权重把雾里朝太阳一侧的散射扣掉（山影、云隙光），不重复加雾。结果按深度升采样（四邻深度相近时双线性，否则取最接近的那个，避免树叶边缘的光晕）后合成：颜色 × 透过率 + 散射光。步进起点每帧抖动，由 TRAA 累积降噪。
- **夜晚**：太阳换成月亮（同一盏方向光，阴影、山影、水面的月光都照常工作）。`SkyDome.setNight` 把天光压到月夜的亮度（`NIGHT_TINT`），加星星（按方向分格抽签）、银河和月面；云按月光照亮。人眼适应的上限放宽到 3.6。座舱：表盘刻度和面板字样从里面亮起来（`CABIN_NIGHT`，贴图亮的部分自发光），屏幕调暗（屏幕也过曝光，要除回来）。机头着陆灯是一盏聚光灯（只在夜晚放进场景，多一盏灯所有材质都要重新编译）；路灯、高杆灯、停机坪边灯在 `nightLights.ts` 里是两次实例化绘制的加法面片。
- **雨刷**（`cockpit.ts`）：转轴用射线落到风挡上，臂和刮片绕玻璃法线转，雨大开快档；刮过的扇形里水膜很薄。停着时收在风挡下沿外面。
- **座舱小零件的图层**（`cockpit.ts`）：旋钮、开关、指示灯、指针、显示屏、表盘玻璃（约 190 个网格）放在图层 4。从外面看时按眼点到镜头的距离、视角和画面高度算一颗 2.5 cm 的旋钮占几个像素，小于 1.2 个像素主相机就不画这一层，大于 1.6 个再画回来；座舱视角一直画。它们本来就不投影，点按钮也是几何判定，都不受影响。
- **风挡倒影**（`cockpit.ts`）：反射光线落在遮光罩这个已知的平面上，到画面里取那一点的颜色，一次采样；按菲涅尔叠加，玻璃是 alpha 混合，发光项要除以 alpha。
- **分层阴影隔帧更新**（`sunShadows.ts`）：阴影占一帧绘制调用的一半以上，CPU 是瓶颈。最近一层每帧画，往外隔 2、4、8 帧，错开在不同的帧里；相机转过一定角度或走出一段距离就立刻重画。每层阴影只有深度贴图：three.js 默认还给每层带一张同样大小的颜色贴图（只有“透光阴影”才读），这里拿掉，极高画质（4 × 4096²）省 268 MB 显存。
- **时段**（`src/render/timeOfDay.ts`，简报里选择，只影响画面）：清晨 / 黄昏把太阳放到 6~8° 高（地图可用 `sunDawn` / `sunDusk` 自定）；天空亮度标定、阳光强度、环境光随太阳高度（`SkyDome.dayK`）变暗，阳光颜色由大气透射算出（自然变成橙红），曝光只补回一部分；清晨的贴地薄雾约 3 倍、更厚，清晨与黄昏的低空霾 1.7 倍；CSM 的 `lightMargin` 随太阳高度加大，远山的长影能投进谷里。
- **雨天湿润**（`src/render/wetness.ts`）：建筑模型（顶点色材质与贴图材质，加载时换成节点材质）、程序道具材质按天气的 wetness 变深（× 0.7）、粗糙度趋向 0.12；朝上的面湿得最透，竖直墙面约三成，檐下几乎不湿。地形有自己的一套。
- **座舱玻璃**：除了雨滴与雨痕，还有一层灰尘与擦拭痕（两层噪声），平时几乎看不见，视线接近太阳方向时按 cos¹⁰ 发出眩光。
- **云影**（`src/render/cloudShadowMap.ts`）：每帧把头顶云层沿太阳方向的透过率画进一张 512² 贴图（覆盖相机周围 16 km，按纹素对齐），所有受光材质（太阳光的颜色节点）和体积雾查同一张图；云的密度与天空里的体积云是同一个函数，所以云影的位置、形状跟看到的云一致。只在开启体积云（高、极高）时有效。
- **光线追踪开关**：浏览器没有硬件光线追踪接口（WebGPU 标准里没有），但这个世界的主体是一张高度图，光线在高度图里走就是真的光线追踪，看得到画面外的山。开关只在不开时的画面上加东西，水面倒影、体积雾、GTAO 一层都不换。`src/render/giField.ts`：进图时在显卡上给地图每一格（512×512）放一个探针，各发 128 条光线（斐波那契球面，所有探针共用一组方向，所以没有噪点），碰到地面按颜色、朝向、山影算反上来的光，碰到水面算反射的天光和碎金，走三轮就是三次反弹，结果存成一阶球谐（平均亮度 + 从哪边来）。太阳在一局里不动，所以只算一次（约 30 ms），飞行时每像素只多三次纹理读取。后期按像素的世界坐标和法线取值，乘上 G-buffer 的反照率。金属、玻璃沿镜面方向走同样的光线，映出地形和水面。舱内补光读探针图在内存里的一份，跟着脚下的地面变化。试过 three 的 SSGI / SSR / SSS，都不合适：SSGI 把天空也当成光源，阴影全被冲灰，平均亮度高 10~30 级；SSR 在屋檐和门板边上是一排锯齿；SSS 在白色机身上是一片噪点；而且当时开关一开就把水面的三段倒影关掉了。
- **透明物体与辅助通道**：法线、漫反射、运动向量通道设成“跟随材质混合”，透明材质（玻璃、光柱、雨、云）写 alpha = 0 的值即保持后面不透明物体的数据（WebGPU 后端按渲染通道上的设置决定逐通道混合）；水面改为不透明 + 最后绘制，用折射采样代替半透明。
- **阴影分层与图层**：CSMShadowNode 四层（4 / 40 / 320 / 2600 m）。图层 1 = 只在远处的物体（中景 / 远景模型、较粗的地形块），图层 2 = 能进最近两层阴影的物体（座舱内部只在图层 2）；最近两层只画图层 2、外面两层画图层 0 和 1，避免把远处物体逐层提交（CPU 绘制开销是这一代渲染器的主要瓶颈）。
- **只投影的合并网格**（`src/render/shadowProxy.ts`）：GLTFLoader 把多材质网格拆成一组单位变换的子网格（座舱固定件 31 个、机身外壳 14 个、座椅 8 个、操纵杆、桨毂、尾桨……），阴影通道里材质用不上，却要逐个提交。同一组里正反面、图层相同、不镂空不透明的子网格合成一个只有顶点位置的网格，挂在组下面跟着组动；它在图层 5（近两层阴影）/ 6（远两层阴影），主相机不开这两层；原网格不再投影。座舱视角阴影每帧提交 241 → 144 个物体。
- **远处的小东西按像素决定画不画**（`src/render/screenSize.ts`）：每帧记下镜头“1 米远处 1 米长占几个像素”，风向袋（2.8 m）、旗子、补给无人机的机身远到不足 1 个像素就不画，超过 1.4 个像素再画回来（长焦、高分辨率会画得更远）；无人机的信标灯一直画。无人机的机架、四个桨盘、吊舱各合成一个网格，所有无人机共用。
- **其他**：分块地形 LOD 与裙边、视锥剔除、雨线与云层、闪电。程序地图的 256 块地形合成三批提交（`terrainView.ts` 的 `ChunkBatch`：近景 LOD0 / 中景 LOD1 / 远景 LOD2、3，各自的投影和阴影图层），每批按槽位预留顶点，块换级时写进新一级的空槽位，每块仍单独视锥剔除、由近到远画；以前每块一个网格，主线程每帧光地形就要一两毫秒。
- **画质档位**（低 / 中 / 高 / 极高）只影响渲染（分辨率、阴影距离与精度、树木与建筑的细节距离、地形细节与照片材质、抗锯齿、环境光遮蔽、泛光、体积云步数、雨密度），**不影响物理和碰撞**；光线追踪是独立开关。首次启动按显卡选择（WebGL2 后端按驱动报告的型号、WebGPU 后端按厂商与架构）：集成显卡选低画质并在主菜单提示切换到独立显卡。
- **舒适性**：视野、镜头抖动、头部晃动可调；动态模糊默认关闭；闪电可关闭。

### 反扭矩（`src/sim/flight.ts` 的 updateSim）

超仿真里机身要受主旋翼的反扭矩 `qMain = 轴功率 / 旋翼角速度`，方向把机头往右推。悬停大约 6900 牛米，总距联动（`simPedalMix`，真机的总距-偏航补偿）在脚蹬中立时顶回去约 5100，所以中立脚蹬下还差约 1800 牛米，关掉增稳后机头每秒往右转 35~45 度，大约要 10% 的左脚蹬才能顶住。这个比例是真实飞机的做法：巡航时脚蹬接近中立，悬停和爬升要左脚。增稳开着时偏航阻尼器把 `qMain` 整个补掉，所以开着不转。

键盘飞脚蹬有两个问题，都在这里解决：

- **只有按和不按**：10% 的脚蹬在满行程上只是 0.1 秒的事。`pedHold` 让刚按下时走得慢（每秒 40%），按久了才快；总距的 `colHold` 同理，点一下是微调，按住才是用力提。
- **松手回中**：真机的脚蹬没有回中弹簧。增稳关着时 `trimPedal` 跟着 `ped` 走，踩到哪里留在哪里；增稳开着时脚蹬要的是转弯速度，松手回中。

滑橇的摩擦（`src/sim/gear.ts`）以前只按速度算，任何持续的力都能推着飞机慢慢走：旋翼一转，机头在地上每秒蹭 0.6 度。现在慢到 0.15 m/s 以下就“粘”在地面的一个点上，力由偏离这一点多远来算。

### 超仿真教学（`src/game/simTutorial.ts`）

和基础教学共用 `Tutorial` 类，课表换成 `SIM_LESSONS`。多出来的东西：`control`（这一步要点的控件，外面亮一圈，不在视野里时告诉玩家往哪边看）、`live`（HUD 收起来了，要看的数字写在卡片上）、`quick`（自转时分秒必争，完成了不停下来打勾）、`Lesson.jump`（学完上一课接着学时也回到这一课的起点）、`Lesson.park`（停在坪上，发动机已经在转）。`tests/sim-tutorial.test.ts` 里有一个只会按键的学生，每一帧走真实的物理把课程学一遍。

### 超大地图

`MapDef.flightSize` 比 `size` 大。核心区还是 `size`（物理和细节都在这里），`Heightfield.outer` 接中圈的 10 米高程，`heightAt` 出了核心区自动查外面一层，所有用地面高度的地方不用改。物理上多加一张 Rapier 高度场，核心区那一块压到地下（`sunkenCore`），两层不打架。边界墙在 `flightSize/2`。GPS 的地图也按这个范围画。外圈的影像只有 10 米一个像素，认不出树，`outerForest` 在几个景点周围种一片，飞到跟前不是一片光地。`tools/bigmap.tool.ts` 用真实地形验证外圈能落地、边界挡得住。

### 真实地形（`src/render/realTerrain.ts`、`src/world/realData.ts`、`tools/real/`）

大峡谷是第一张用测绘数据的地图，走一条和程序生成地图并行的路：`MapDef.real` 有值时，`generateWorld` 读高程而不是算高程，`WorldView` 建 `RealTerrain` 而不是 `TerrainView`。

- **三层嵌套**：核心 10.24 km（2.5 米一格，物理、碰撞、飞行都在这里）、中圈 41 km（10 米）、远圈 164 km（160 米，只看不飞）。外面两层把地球曲率烘进了高度。
- **网格**：CDLOD。一块 64×64 的网格实例化绘制，四叉树按距离选块，顶点着色器用 `textureLoad` 取高度，快换级时奇数顶点滑向粗一级的位置，裙边遮缝。最细一级和 Rapier 高度场的三角剖分一致。
- **从照片到反照率**（`prep_grandcanyon.py`）：航拍里有拍摄时的太阳。坡面明暗只除掉八成，亮度和饱和度不再调：原片的色调本来就对，以前提亮之后内峡谷的片岩成了土黄色。算出来的影子只当候选范围，真正够暗的才算影子（`refine_shadow`：比同一层晒太阳的岩石暗一大截也算，航线接缝那边是另一天拍的，只看绝对亮度分不出来）。
- **影子修复**（`fill_shadows`）：影子里的岩层和沟壑照片上都在，只是暗。亮度先按块对齐到同一层晒太阳的岩石，一百多米以内的起伏全用照片的，放大一点对比度；颜色借附近同一层晒太阳的岩石（`local_colors`，1.3 公里一块）；灌木和碎石的斑点影子里看不见，从紧挨着的晒太阳的地方镜像借过来，高度差太多的不借。影子的边不可信，留着是一条细黑线，这一圈只用平滑的底色。
- **崖壁**：航拍是从正上方拍的，接近竖直的面只有一条缝。七十度以上的面改查岩层色表（`strata.png`，4096 像素，0.44 米一格，细的层理也写在里面，远处靠 mipmap 平均掉），明暗取照片的低频，再加雨水痕迹。地层不是水平的：让崖壁的高度分布最集中，拟合出往北每公里抬升约 16 米（`dip`）。色表的透明通道是这一层岩石有多硬，着色器按上下两点的差算出层的底面朝下、暗。层理的强弱按地层给（`FORMATIONS`）：凯巴布和苏派一级级的，红墙和科科尼诺是一整面的，页岩弱，毗湿奴片岩是变质岩，没有水平的层。
  - **颜色**：从航拍统计的色表各层都差不多，是坡上的土色（竖直的面在照片上只有一条缝）。`FORMATION_RGB` 写着每层实际的颜色，统计结果往上靠六成，大峡谷红的红、白的白才分得出来。
  - 程序地图的岩壁（`terrainShader.ts`）也有这个问题：浮雕图是一面有层理的悬崖，峡湾和喜马拉雅的花岗岩、片麻岩不该有一层层的横纹，整面墙像毛毯。`RockFormDef.massive` 的地图用另一张浮雕图（`rock_relief_block.webp`，真实块状岩体的法线），三个尺度各转一个角度。
  - 这两张图的山像不像石头，贴图只占一小半，主要看形状：`bench` 和 `warp` 开小了就是一面面光滑的泥巴锥，什么贴图都救不回来。地形一格 4 米，二十米一级的扭曲画得出来。手工生成的 Voronoi 和节理线试过，看着像干裂的泥和划痕，不如真实岩面的法线。
  - **起伏**：高程 2.5 米一格，竖直的面上只有几个点，贴上岩层就是一张木纹贴面。着色器里用两层噪声假装有起伏：几十米到几米的石柱和沟，一块块沿着岩层躺着的岩体。法线按起伏的坡度摆，凹进去的地方暗，雨水痕迹和层的底面线都跟着断开。墙的朝向过 45 度的地方接不上，mipmap 级别要自己算（`lvOf`），不能靠屏幕导数。
- **近处的地面**：45~240 米以内影像换成十来米尺度的底色，灌木和碎石的斑点放大了只是一团糊，这个距离上它们已经是立体的了。细节层三层：近处的碎石、中间的土、远处的大块明暗。
- **陡坡**：三十多度以上的坡从正上方贴细节会被拉长，改成贴在坡面上，一层几米、一层几十米（坐标用噪声扭过，大面积山坡上看不出一格一格）。明暗用的法线和十几米尺度的平均法线比，差的部分放大（`Nsharp`），山脊和沟的边才利；山的形状和碰撞不变。
- **外圈的林子**（`realScatter.ts` 的 `TREE_RING`、`TALL_RING`）：矮树一圈，高处再加一圈西黄松，疏密按十几米尺度的影像估，所以贴图取第 1 级 mipmap（一个像素 5 米，单看一个全是噪点）。没有西黄松的话，一过核心区的边林子就矮一截，地上看得出一条线。七十多米以内换成全细节的模型（`TREE_SWAP`，同一批树，种子一样）。
- **外圈树的碰撞**：这些树只存在于显卡上。`RealScatter.probe` 飞低了才工作，每 0.4 秒用同一段着色器（`cellAt`）把机身周围 32×32 格算到一张小贴图上读回来，`GameSession.setRingTrees` 收到后和核心区的树一样生成碰撞体。画面和碰撞用的是同一份计算，不会有“看得见撞不到”的树。
- **地面散布**（`realScatter.ts`）：黑灌木、碎石、枯草，全部放在显卡上。世界按格子切开，每格用格子坐标的哈希决定有没有东西、放哪儿、多大，高度从地形的高度贴图取（三角剖分和地形一样，外圈 20 米一格，差一点就悬空），疏密看 `scatter.webp`（R 灌木，G 碎石，B 枯草）。每帧只传镜头所在的格子号，没有实例数据要上传。灌木用 `trees.glb` 里的 `scrub`，近圈投影，旋翼气流吹得动。画质档位控制格子往外几成（`SCATTER_RANGE`）。外圈的影像看不出灌木，疏密按颜色和坡度估；也认不出树，高处深绿的地方种一圈矮松和刺柏（只有画面，撞不上）。
- **河**：青绿色，离岸远的地方深（辅助图的 G 通道里写着离岸多远）。倒影沿反射方向在高度图里走 15 步，撞到崖壁就取那里的影像，撞到的地方天空不再反射。白浪是比周围的水亮一截的地方，不能看绝对亮度。河面用颜色和谷底的高度一起认（`river_mask`），高度压平（`flatten_river`）。外圈也能飞，所以有自己的辅助图（`sky_river_mid.webp`，20 米一格），河不会一出核心区就变回影像上的颜色。
- **房子和桥**（`realBuildings.ts`、`maps/grandcanyonBuildings.ts`）：照着航拍描的八十栋房子和两座吊桥。屋顶的颜色就是航拍本身，从上面看和照片一样，只是立起来了。屋檐伸出墙外，墙上有水渍和石头墙基，窗玻璃反光，夜里一部分窗户亮灯（`night` 跟着天色）。碰撞框在 `generateWorld` 里加，房子里面不长树。
- **散布的开销**：顶点着色器里要查地形，开销全看顶点数。碎石用共用顶点的几何体（面法线由着色器算，12 个顶点，不是 60 个）；远的灌木用三片卡；外圈的树够不到核心区外面时整圈关掉，否则一棵不长也要跑几百万个顶点（这一项之前每帧白花 3 毫秒）。
- **仪表屏**：画布传到显卡很贵。一帧最多重画两块，各按各的频率（姿态仪 20 Hz，超仿真以外的无线电这些屏 2 Hz），在外面看的时候不画。
- **运动向量**：位置全在着色器里算的网格（地形、散布）要标 `userData.placedOnGpu`，否则“上一帧的位置”是几何体的原始坐标，运动向量大得离谱，时间抗锯齿等于没开（`instancing.ts`）。
- **辅助图**（`sky_river.webp`，5 米一格，无损）：R 岩缝，G 河面，B 看得到的天空（16 个方向找地平线，余弦加权，看到两公里外）。天空可见度进 `aoNode`，峡谷深处才暗得下去。河面来自激光测绘的压平水面：谷底又平又连成一片的地方。
- **山影**：`sunMap` 一张贴图的左右两半分别是核心区（5 米）和中圈（20 米），不多占采样器。两半要一样大，总宽不能超过 8192，所以中圈的高程在这里隔一格取一格（`SUN_CELLS`）；影子不需要 10 米的精度。
- **树**（`trees.dat`）：航拍上周围亮、中间暗的斑点。南缘是矮松和犹他刺柏（`pinyon`、`ujuniper`，各两种形状，灰绿色，多干，一团团的；新树种加在 `TREE_TYPES` 后面，别的地图不变），高处影子最黑的那些是西黄松（`ponderosa`，二十米高，林子才有高有低），溪边是三角叶杨，大的灌丛也在这里，小的归地面散布。位置是真的，大小和种类按高度估计。
  - **叶卡**：一格贴图上的叶子要成团，撮和撮之间留大缝。细绳一样的枝缩小以后是一块实心的布，树冠成了迷彩球。图集按格子填透明区的颜色，叶卡的 UV 往里退 8 个像素，矮松不和白桦树皮挨着：白色从隔壁渗过来就是树冠上一道道白线。
- **采样器上限**：片元着色器 16 张贴图、16 个采样器（WebGPU 默认）。层与层之间的过渡烘进影像（`blend_edge`），天空、河面、岩缝合成一张，细节层的法线和明暗合成一张（`terrainLayers.ts` 的 `PACKED`），都是为了省采样器。现在正好 16 张、15 个采样器（高度贴图用 `textureLoad`，不占采样器）。调高上限靠不住：这台电脑的显卡贴图能到 48，采样器最多还是 16。
- **30 厘米影像**（`render/hiRing.ts`、`world/hiTiles.ts`、`tools/real/fetch_hires.py`、`prep_hires.py`）：NAIP 原始是 30 厘米，核心区全放进一张贴图是 32768²，放不下也下载不起。切成 160 米一块（512×512，0.3125 米一个像素，共 4096 块），镜头周围放一张环形贴图，飞到哪儿解码哪块。
  - **环形贴图**：第 (列, 行) 块永远放在第 (列 mod S, 行 mod S) 个格子，贴图是重复寻址的，世界坐标除以环的宽度就是贴图坐标，着色器不用查表，飞过去只写新进来的一排。中、高、极高一边 4、6、8 块，保证清晰的半径是 240、400、560 米。低画质和 WebGL 不开。窗口的中心放在镜头前方，慢慢跟过去。每格一个权重（uniform 数组），块到了淡入。
  - **放哪儿**：成品 241 MB，放在单独的仓库 `rotor-trails-tiles`（Pages 同一个域名）。放这个仓库的话，每次部署都多传一遍，重新生成一次仓库就多一份。
  - **加载**：`fetch` + `createImageBitmap`（解码不在主线程，512² 约 2.4 毫秒），`copyExternalImageToTexture` 写最细一级，缩小版用一个小渲染通道逐级算（`DOWNSAMPLE`）：画布没法不预乘透明度地缩放，在显卡上算也更快。一帧最多写一块，主线程 0.2~0.8 毫秒。
  - **大尺度的颜色跟着 `core.webp`**：`prep_hires.py` 在 1.25 米的网格上算每个地方要乘多少（8 米的尺度），十来米以内的东西全是原片。所以环形贴图的边上只是清晰度慢慢变，块晚到也只是这一块晚一点变清楚。这个倍数要在拼好的整张图上算，块的边才接得上。晒太阳的地方和影子分开算，混在一起的话影子的边上一圈都是错的。
  - **影子分开存**：RGB 是没有影子的地面颜色，A 是这个像素在航拍里晒得到太阳的程度。影子用近红外找：树冠在近红外里和地面一样亮，影子全黑；可见光里两个都是暗的，分不开。近红外下的是 0.6 米一格，边用导向滤波贴到可见光上。大片影子里的树只有天光，近红外不够黑，挨着大片影子又暗的像素也算影子。
    - **小块的影子**（树和灌木的）：提亮到和旁边晒太阳的地面一样，影子本身写进 A。A 进 `receivedShadowNode`，只挡直射光：和实时影子挡的是同一份光，叠在一起也只暗一层。太阳和拍摄时差 15 度以上慢慢不用，到 35 度完全不用（`sunMatch`）：游戏白天的太阳和航拍差 10 度，清晨、黄昏、夜晚都不用。
    - **大片的影子**（山的）：A 里不写，实时影子自己会画。这一片是拍摄那天那个时刻的太阳，和游戏的太阳不一定对得上，写进去就是阳光底下一片又黑又花。颜色和对比度按旁边晒太阳的地方拉回来（`unshade`）：每个通道取对数，影子里的平均和起伏对上晒太阳的地方，这样影子里的树是绿的、路是红的，影子里的步道也看得见。旁边几百米都没有晒太阳的地方时用更远的统计（`stat`）。起伏只放大到 1.45 倍，再大近处看着发花。
    - A 只有三档。连续的透明度压缩以后比颜色还大（每块多 30 KB），三档只多一成多。提亮用的是同一份三档的值，颜色 × 光照 在拍摄时的太阳下还是原片的样子，三档的边不会露出来。
  - **树冠是贴纸**：地上站着三维的树，照片里的树冠贴在地上就是一地的贴纸。`trees.dat` 的位置是 1.25 米影像上暗斑的中心，也就是树冠和影子一起的中心，平均偏 2.7 米。`prep_hires.py` 用 NDVI 找到真正的树冠，把树挪过去（从 `trees_orig.dat` 开始，跑几遍结果一样），挪上去的树冠从照片里抠掉换成地面（`fill_ground`，和 `fill_shadows` 一个办法），它的影子也不要，实时影子会画。没有三维树的小树和灌木留在照片里。
  - **近处**：30 厘米放大到一格十来个像素还是软的，一团团的树冠更糊。20~110 米以内比周围暗一截的地方换成底色（环形贴图的第 4 级），别的地方退一半，路面、屋顶、石头都还在；这个距离上影子也不用，投影子的东西已经立在那儿了。细节层到 90 米都是全强度，320 米外才让位给照片。底色要指定级别取，走各向异性贴地看过去会拉出放射状的条纹；放大这么多倍线性插值看得出一格一格的方块，所以用三次 B 样条（四次取样，`smooth`）。
  - **灌木长在照片上**：环形贴图覆盖的地方，灌木的疏密不看 `scatter.webp`，看照片上这里是不是比周围暗一截（`bushAt`，顶点着色器里查）。没有三维树的小树和灌木留在照片里，这样它们身上站着一丛立体的。
  - **其他**：屋顶和地面一样换成 30 厘米的。河面的白浪还是看 1.25 米的影像：30 厘米的水面是影子里提亮的，亮点全成了一河冰块。50~70 度的坡颜色换成岩层，30 厘米的照片这个坡度上台阶拍得出来，留三成多，留多了崖边是一排竖着的牙。离地 1200 米以上一个像素比 1.25 米还粗，不下载。
- **高程数据**：`fetch_grandcanyon.py` 走的在线服务在中西部只有 10 米的数据，1 米的项目 `AZ_GrandCanyonNP_2019_B19` 没飞到这一块。`AZ_NWGrandCanyonNP_D25` 2026 年 10 月才发布，服务里还没有，所以单独下载（`fetch_lidar.py`，266 MB），`merge_lidar` 平均到 2.5 米换上去，占核心区 26%。两个项目的中位高差只有 0.01 米，边上 60 米过渡。托恩托平台上有几块看着很光滑，那是页岩缓坡本来的样子，1 米原始数据里也是这样。
- **文件名**：`.bin`、`.gz` 这类后缀会被下载软件（比如 IDM）拦走，网页只收到一个空的 204；`aux`、`con` 这些是 Windows 的保留设备名，Git 打不开。见 `tests/real-data.test.ts`。高程用 `.dem`，树用 `.dat`。文件是 gzip 压缩的，有的服务器会替浏览器解开，所以读的时候看文件头。

### 声音：电影镜头（`App.listenFromCamera`、`audio.ts`）

电影镜头里耳朵在摄影机那里：旋翼声按距离衰减（`1 / (1 + d / 60)`），高频先没（低通 `20000 / (1 + d / 22)`），飞机朝耳朵过来音调高、过去了音调低（多普勒，直接乘在合成器的转速上）。座舱和追尾不算。

### 声音：山壁的回声（`src/sim/echo.ts`、`audio.ts`）

一秒四次，左右各看三条线，往外走到 520 米，碰到比飞机高（减 8 米）的地面就是一面墙。发动机总线分一路出来，过 1300 Hz 低通，进左右两条延迟线（`2d / 343` 秒，声像各偏一边），两面山壁之间再来回一次（反馈）。延迟时间平滑地变，所以离山壁越来越近的时候回声的音调真的会变。座舱里音量减半。

### 撞击、受损、坠毁（`src/render/wreckFx.ts`、`GameSession.stepWreck`、`CameraRig.crash`）

只有画面，不影响飞行。撞击按飞机所在的地方分三种：贴地扬尘、水面溅水、半空只有碎片和火星。耐久低于 60 拖烟，越低越黑。耐久低于 66、34 风挡分两级裂开，裂纹是一张画布贴图（红、绿两个通道各一级），修好就没了。坠毁之后 `step()` 走 `stepWreck`：不再算升力，残骸带着撞完的速度翻滚着掉到地上；任务和休闲飞行的镜头退到撞之前的方向上看着它，2.8 秒后出失败页。教学里撞了直接回安全点，不看残骸。

### 停机坪上的货（`src/render/padLife.ts`）

卸货完成的坪上堆一批木货箱（`tools/blender/crate.py` 导出的 `models/crate.glb`，一次实例绘制），货箱跟着任务状态走，重来就没了。以前每块坪还站着一个地勤，2026-11-08 按用户要求人物模型先全部撤下（“这个我之后再想办法”）。

### 手机和平板（`src/ui/touchControls.ts`）

只有触屏、没有鼠标的设备（`?touch=1` 可以在电脑上看）：左摇杆升降和转向，右摇杆前后和平移，和航模遥控器的“美国手”一样，手指按在哪儿摇杆就到哪儿。摇杆的量走 `Input.padAxis`（和手柄同一条路），所以教学判断“按住了没有”、飞行手感不用另写。屏幕其余地方拖动转头。提示里的键名由 `keyName` 换成摇杆和按键的名字。超仿真要用鼠标按开关，手机上不给选。画质从低档开始。

### 背景音乐（`src/audio/music.ts`）

实时生成，没有文件：慢慢换的和弦（五个和弦、固定的走向）垫底，偶尔几个钢琴一样的音，只取 D 大调五声音阶，所以随机走也不会难听。任务和教学不放（要听发动机和告警），菜单全音量，休闲飞行四成，自动巡航和回放八成。

### 回放（`src/game/replay.ts`、`App.openReplay`、`src/ui/replayPanel.ts`）

飞行时一秒录 15 帧（时间、位置、姿态、速度、转速、升力、空速），录最近四分钟，放在环形缓冲里。位置用速度做三次埃尔米特插值，姿态球面插值，放出来是顺的。停在地上不动的时候不录（超仿真的冷舱启动没什么好看的）；两帧之间跳了 30 米以上就是传送。教学不录。

回放不碰物理：`session.body`、`session.prev`、转速、升力、空速先存一份，放的时候把录下来的写进去给画面和声音看（镜头、下洗、水花、多普勒都自动跟着走），放完写回去。物理一直没走，继续飞接得上。慢放是把渲染的时间缩到 0.35 倍，云和水也跟着慢。放的时候能进拍照模式，退回来还在回放里。

飞行里传送过（选景点、从检查点继续、撞了回到空中）的地方前后两段都留着，算一个剪辑点：两段之间不插值，镜头跟着切。

### 地名字幕（`src/game/places.ts`、`src/maps/placeNotes.ts`）

休闲飞行才有。地方 = 地标 + 景点，按名字合并。飞进半径（景点 300 米、地标 420 米；同名的地标半径要盖住它的景点机位，菜单跳过去也算到了）就淡入地名和一句话，字幕之间至少隔 30 秒，一趟飞行每个地方只报一次。第一次来的多一行“到过 3 / 7”，写进存档的 `visited`。菜单只能跳景点，地标要飞去：暂停菜单写着方向和距离，点一下让自动巡航先飞到那里（`ScenicCruise` 的 `first`），超仿真就只写方向。大峡谷的那句话写真事，其他图是虚构的，写这种地貌的真事。自己按 U 收起 HUD 时不显示，到访照样记；超仿真默认没有 HUD，字幕照样有。

### 下雪和积雪（`src/render/weatherFx.ts`、`src/render/wetness.ts` 的 `COVER`）

雪花是雨的那套粒子换一组参数（`FallStyle`）：落得慢、宽、不拉长、左右飘。`COVER`（0..1）是地上积了多少雪，`min(1, 雪量 × 1.6)`，下雪时慢慢涨（时间常数 20 秒），一进图就在下的话已经积好了。地形、房子、树、草、石头、水里的倒影共用这一个数：朝上的面白，陡的挂不住，雪薄的时候地面是一片片的，树冠只白上面。风挡上化成水珠，下洗卷起来的是雪沫。

### 雨线和闪电（`src/render/weatherFx.ts`）

雨线和雪片是面片，在顶点着色器里转向镜头，绕向算下来是背面，材质必须是双面（只画正面的时候，一条都看不见）。雨线和雪片的亮度乘天色，不然夜里满天白线。

闪电以前只有天空一闪。现在打雷时在 CPU 上生成一次形状（`LightningBolt`）：云底到地面用中点位移抖成折线，五根分叉，面片朝镜头，颜色给到 HDR 的十几倍，泛光自己会带出光晕。大多打在镜头前方 ±63° 以内；距离和雷声的延迟用同一个数，隔多少秒听到雷就是打在多远。

### 极光和银河（`src/render/sky.ts`）

极光是把天空方向投影到一个水平面上（`d.xz / (d.y + 0.2)`），从下往上走 20 层：每层用两个噪声把两条带子弯一弯，再用一个沿带子方向变化的噪声切成竖着的光柱，下面绿、上面紫红，亮度往上衰减。水面倒影走 6 层。只有 `MapDef.aurora` 的图有（峡湾）。

银河是绕天球一圈的带子：宽度和颜色随离银心的角度变，银心那段鼓起来、偏暖；中线一道尘埃暗缝，位置用模糊过的噪声扭一扭。噪声一定要取模糊过的 mip：原图对比太强，天上是一块块的脏斑。星星三层，半径按格子算，比一个像素小就被时间抗锯齿抹没了；银河里抽中的概率高。流星十三秒抽一次签，七成概率有，一条 0.85 秒的亮线。

### 拍照的风格（`LOOK`，`src/render/post.ts`）

调色最后一步多三个数：饱和度、冷暖、黑位抬高，退出拍照模式还原。不走单独的通道，存下来的图里就是这个样子。

### 机场的灯（`MapDef.lights`，`src/render/nightLights.ts`）

光点，没有地面光斑：跑道两边每 60 米一盏白灯，南头绿灯、北头红灯，南边七排进近灯，滑行道蓝灯，黄昏和阴天跟着路灯一起亮。

### 绕场的飞机（`src/render/traffic.ts`，位置在 `src/sim/movers.ts`）

`MapDef.traffic` 给一条闭合航线（世界坐标），Catmull-Rom 插值后按弧长等分。机头跟着航迹，坡度从前后 30 米的航向差算（`atan(v²·曲率 / g)`，取刚飞过的 36 米的平均，坡度是慢慢压上去的），比航迹高 3 度迎角。螺旋桨是一层淡圆盘，所以模型单独导出一个没有桨叶的 `plane_fly`。撞得上（8 个盒子：机身、上单翼、平尾、垂尾、起落架）。

### 船的尾浪（`src/render/vessels.ts`）

沿船走过的航线往后铺一条带子（28 排，船边上密、后面疏），从船头前 0.42 个船长开始（船首波），每排横向宽度 = 离船头的距离 × tan 19.5°（开尔文角），船边上至少半个船宽；平贴在水面上 5 厘米（不跟着船身横摇和起伏），深度往前挪一点避免和水面打架。以前尾浪是挂在船上的一整块三角板，船身横摇 0.7° 时一百多米宽的一边沉到水下，看上去只剩一边、一截，转弯时整块甩着扫过水面。

## 10. 存档与兼容性

- 休闲飞行到过的地方（`visited`）和飞行记录（`log`：离地时间、平安落地次数、最轻的一次接地、存下的照片）是后加的字段，旧存档读出来是空的，不用升版本。
- 本地存档带版本号（`rotorTrails.save`，当前 v4；v1→v2 把仍是旧默认值的“下降 = Ctrl/X、视角回正 = C”改成“下降 = C、视角回正 = Z”，v3→v4 再把“下降 = C、动力增强 = Shift”互换，玩家改过的键位不动），逐项校验并夹取范围；JSON 损坏时回退默认值并把原数据备份到 `rotorTrails.save.corrupt`；存储不可用（隐私模式等）时提示“进度不会被保存”，游戏照常运行。
- 启动时检查 WebGL2 与 WebAssembly，不支持时显示原因和解决办法，而不是黑屏；脚本下载期间显示加载画面。
- 鼠标观察优先使用指针锁定（需要用户点击）；浏览器拒绝时退回“按住左键拖动”。
- 浏览器快捷键冲突：Ctrl+W 等无法被网页拦截（按住 W 再按 Ctrl 会关闭页面），所以默认键位不用任何修饰键：爬升 = 空格、下降 = Shift（Shift 不是浏览器快捷键的一部分，按住 W 再按 Shift 没事）；飞行中关闭页面前弹出确认；窗口失焦时清空按键状态。
