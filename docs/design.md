# 设计与技术方案

本文档说明 Rotor Trails 的整体架构、各个系统的实现方式和五张地图的关卡设计。数值都来自代码中的集中配置（`src/config/flight.ts`、`src/sim/damage.ts`、`src/sim/buffs.ts`、`src/sim/scoring.ts` 和各地图文件），改配置即可调整手感与难度。

## 1. 架构

```
浏览器帧（requestAnimationFrame，帧率不固定）
  └─ FixedStepper：把帧间隔换算成固定 1/60 s 的物理步（单帧最多 6 步，超长帧截断）
       └─ GameSession.step()（纯仿真，不依赖 DOM，可在 Node 里运行和测试）
            天气 → 风场采样 → 近地射线 → 起落架力 → Buff 计时 → 飞行模型（力/力矩）
            → Rapier 物理推进（唯一的位置积分）→ 碰撞与损伤 → 接地/降落判定
            → 补给拾取 → 维修站 → 任务 → 导航 → 地形告警
  └─ 渲染（three.js）：按插值系数在上一步与当前步之间插值显示，与物理解耦
```

- **唯一的运动真相**：直升机的位置和速度只由 Rapier 刚体积分；飞行模型只输出力和力矩，渲染只读取状态。
- **固定步长**：物理结果只取决于步数，与显示器刷新率无关（测试覆盖 30/60/144 FPS 与抖动帧）。切后台、卡顿后的超长帧被截断，不会一次补算导致“瞬移”。
- **暂停**：暂停时不推进仿真，Buff、阵风、天气等所有计时都基于仿真时间，因此一起冻结。页面切到后台自动暂停。
- **模块化、配置驱动**：地图是数据（地形函数、站点、航点、航段、任务、天气、风区、道具），新增地图不需要改引擎代码。

## 2. 飞行模型（`src/sim/flight.ts`）

参考一架约 1750 kg 的轻型单旋翼直升机（旋翼半径 5.3 m）：

- **旋翼推力与功率**：动量理论诱导功率 + 型阻功率 + 爬升功率；可用功率 = min(传动限制 340 kW, 发动机 470 kW × σ^0.7) × 耐久性能系数 × (1 + 动力增强)。σ 为空气密度比（随海拔指数下降，每升高 1000 m 约降 11%）。
- **桨叶失速限制**：总距满行程时的推力 = 2.2 × 基础重量 × σ，并保底不低于当前重量的 1.12 倍——任何海拔、任何载重下都不会出现“无法起飞/无法脱离”的死局。海平面和高原上都先受功率限制。
- **惯性与气动**：机身三方向阻力面积、桨盘 H 力（低速时更大）、升降阻尼、平移升力（ETL）、地面效应、桨盘后倒与上反效应、风标效应、主旋翼反扭矩与尾桨。
- **风通过相对气流作用**：所有气动力都用“机体速度 − 风速”计算，风不会被辅助系统抵消掉。
- **起落架**：四个滑橇支点的射线弹簧-阻尼模型，带静摩擦，可以稳定停在坡面上。

### 三档辅助（`ASSISTS`）

| | 新手 | 标准（推荐） | 挑战 |
| --- | --- | --- | --- |
| 姿态 | 松杆自动改平并缓慢减速 | 松杆改平，保留惯性 | 角速度控制，松杆保持当前姿态 |
| 垂直 | 保持高度，近地自动限制下降速度 | 保持垂直速度，近地限制下降速度 | 总距直接控制升力 |
| 反扭矩 | 完全协调 | 完全协调 | 不完全协调 |

- **悬停辅助（H）**：逐渐减速（不是瞬间锁定），低速时用积分项抵消持续风，速度足够低后保持位置；滑橇触地后自动关闭。
- **下降限制**：离地越近允许的下降速度越小；按约 0.7 s 后的离地高度预判，并在动力余量小（高原）时收紧。
- **动力上限保护**：持续掉高度时自动减小前倾，把动力留给升力。
- 输入有平滑（上升/回落速率），避免键盘输入造成的突变。

## 3. 风与天气（`src/sim/wind.ts`、`src/sim/weather.ts`）

- **风场** = 基础风（方向缓慢摆动）+ 连续湍流 + 局部风区。风区为胶囊形区域，可限定高度范围，分三类：
  - `channel` 通道风：把风扭转到通道方向（峡谷顺谷风、山口下坡风）
  - `gust` 规律阵风：周期可预测，HUD 提前约 3 秒预警“阵风将至”
  - `lift` 垂直气流：上升/下沉气流（迎风坡、背风坡、峭壁）
- **天气**：晴、小雨、暴雨、浓雾、低云、大风等参数组合（风、阵风、湍流、云量、阴天、雨、能见度、低云层高度、闪电、地面湿润），天气之间平滑过渡；“动态天气”会在完成某个任务后转变（例如雨林的晴转暴雨）。
- **风的可见线索**：风向袋、旗帜、经幡、树木摆动、雨线倾斜、风声；HUD 显示风速、来向、阵风和当前风区名称。
- **场景里的导航**：世界里只放现实中说得通的东西——任务目标是烟幕和闪烁的引导灯，补给是悬停的无人机，方向与距离看 HUD 的目标菱形和屏幕边缘箭头；三维光环与箭头是可选项（设置 → 三维航线标记，默认关）。
- **雾和云中的公平性**：HUD 标记不受雾影响；打开三维航线标记时，航点光环、航线箭头不受雾影响（仍会被地形遮挡），信标灯光可穿透雾气；HUD 的航点方向/距离、转弯预告和地形告警始终有效。

## 4. 碰撞与损伤（`src/sim/damage.ts`）

- **耐久 0–100**：70 以上正常；70–30 受损，性能与稳定性逐渐下降；30 以下严重受损，性能明显下降但始终保留控制能力；0 为坠毁。性能系数 = 1 − 0.28 × (1 − d)^1.6，连续变化、没有台阶。
- **按冲量结算**：Rapier 接触力 × 步长 → 冲量 → 速度变化。同一部件 0.45 s 内的接触合并为一次碰撞，按累计速度变化减去容差计算伤害——持续顶着障碍物不会每帧重复扣血。
- **旋翼/尾桨撞击**单独计算并有冷却时间；贴着障碍物高速滑动会持续擦碰伤害。
- **接地**：下降速度、水平速度、姿态超过安全值才扣耐久；轻微重着陆（伤害 < 3）不计入碰撞次数；水平速度很大时归类为“机身撞击”。
- **致命事件**：侧翻、落水（不属于普通碰撞，护盾也挡不住）。
- **维修**：绿色维修坪停稳 4 秒恢复（有使用次数），或拾取维修补给 +25；性能随耐久恢复。

## 5. Buff（`src/sim/buffs.ts`）

| Buff | 规则 |
| --- | --- |
| 动力增强（黄色闪电） | 拾取后储存 1 次（持有时不能再拾取，补给留在原处），按 C 使用；7 秒内可用功率 +25%、爬升上限提高；0.6 s 渐入、1.5 s 渐出 |
| 免伤护盾（蓝色六边形） | 拾取即生效 9 秒；挡住耐久损失，但碰撞照常发生（会被弹开、计入碰撞次数）；重复拾取最多延长到 14 秒 |
| 维修补给（绿色十字） | 立即恢复 25 耐久，不超过 100；耐久满时不被消耗 |

所有补给只能拾取一次；检查点保存/恢复完整的 Buff 状态与已拾取记录，不能通过反复读档刷补给。

## 6. 任务、检查点与评分

- **任务类型**：`land` 降落（停稳后停留数秒卸货/接人）、`hover` 悬停投放（在指定高度区间稳定悬停）、`inspect` 巡查（按顺序低速飞过若干点，可带引导航线）。
- **降落判定**：下降速度 ≤ 2.5 m/s、水平漂移 ≤ 2.5 m/s、姿态 ≤ 12°、落在坪内；右下角着陆辅助实时显示四项是否满足，停机坪被机头挡住时也能用。
- **检查点**：起点、每完成一个主线任务、经过标记的航点时自动保存（位置、姿态、速度、耐久、任务进度、Buff、已拾取补给、天气）。失败后可以：从最近检查点继续、从更早的安全检查点继续、安全恢复（以稳定悬停状态继续，耐久至少 40，计入评分扣分）、或从关卡起点重来。
- **评分（不使用时间）**：主线 600 + 每个可选任务 120 + 剩余耐久 ×2 − 每次碰撞 15（最多扣 180）+ 最终降落质量（最多 200）− 每次安全恢复 60。S ≥ 1050，A ≥ 900，B ≥ 760，C ≥ 620。用时只记录、不计分。

## 7. 导航（`src/sim/nav.ts`）

- 每个航段由一条或多条路线组成；分岔处同时显示各路线的说明、距离和方位，飞向其中任意一条即自动选定（按 N 切换推荐）。
- 三维航点：光环、沿航线的少量箭头；高速时转弯预告提前（预告距离 = max(350 m, 速度 × 14 s)），给出建议速度和高度。
- 偏离航线时给出恢复引导（先爬升到安全高度，再飞向最近的航点）。
- **航线净空检查**（`src/sim/routeCheck.ts`）：沿每条路线检查与地形、水面、建筑（含悬空结构，例如岩拱）、树冠的净空；`autoAlt` 航点在生成地形后按实际障碍自动抬高；`npm run mapviz` 输出俯视图和问题清单，测试要求每张地图 0 问题。

## 8. 世界生成与渲染

- **地形**：每张地图用数学函数（噪声、山脊噪声、样条距离场）生成高度场，再用样条“刻”出河道、峡谷、峡湾、冰川谷，整平站点；同一份高度场同时用于 Rapier 碰撞（已用测试验证三角剖分一致）和渲染。地表遮罩（沙、泥土/道路、无树区、积雪）由生成过程绘制。
- **地形着色**：坡度/高度/遮罩混合草地、岩石、积雪、沙滩，岩层条带（峡谷）、湿润、森林地面；中高画质使用 Poly Haven 照片材质（每张地图 8 层，打包成纹理数组）：平地用俯视投影（近处 + 旋转后的大尺度两次采样打破重复），陡坡逐渐改用三平面投影，照片颜色按亮度保留明暗、色相向地图的生物群系颜色靠拢；积雪按带细节的法线判断朝上程度（雪积在岩石平台与凹处）。低画质退回程序着色。
- **建筑与道具**：道具函数用程序几何体生成碰撞体和后备外观；有 Blender 模型的建筑在 `beginModel / endModel` 之间登记模型实例（位置、朝向、按本栋尺寸缩放），渲染时用实例化网格画模型、跳过对应的程序几何体（`src/render/modelLib.ts`、`propsView.ts`）。模型由 `tools/blender/props_<地图>.py` 生成，参照照片建模、使用照片材质，子网格按材质合并。碰撞体为盒、圆柱、球、胶囊。动态对象（风向袋、旗帜、经幡、信标灯、闪烁灯）由锚点生成。
- **植被**：按密度、坡度、高度和遮罩散布，实例化渲染；只为直升机附近约 85 m 内的树创建碰撞代理。10 个树种由 `tools/blender/trees.py` 生成三级细节（近景：弯曲渐细的枝干 + 法线朝外的叶簇卡片；中景：简化；远景：体块树冠），叶片贴图为程序绘制的图集。叶片用 alpha 测试（多重采样时 alpha-to-coverage），远处按 mip 级别补不透明度避免变稀；顶点着色器按真实风场让树冠摆动、叶片细碎抖动。
- **光照与大气**：Preetham 物理天空（太阳盘、云层银边），环境光照由天空预滤波得到；雾按高度衰减，朝太阳方向带阳光的散射色，云中另有雾浓度。阳光阴影使用四级分层阴影（分界 4 / 40 / 320 / 2600 m），每个受光材质都通过同一个钩子接入阴影与雾（`sunShadows.ts`、`atmosphere.ts`）。
- **水面**：8 组解析波浪（按像素覆盖范围淡出，避免远处摩尔纹）+ 噪声细节；岸边白沫来自水深纹理；亚马孙河为浑浊模式；粗糙度随距离增大。
- **岩层**（`src/world/rockForm.ts`）：峡谷、峡湾、喜马拉雅的地图配了一张地层表（每层的厚度、硬度、颜色）。在雨水侵蚀之后把陡坡改成“硬层成崖、软层成坡”的剖面；地层面可以倾斜、缓缓起伏（几个正弦波相加，CPU 和着色器算出来的值完全一样）。颜色在地形着色器里按同一张表（`strataLUT`，一行 4096 像素的贴图，含纹层和接触线）查，所以层线和台阶对得上，绕山一圈连续。岩壁在水平方向再扭一扭（`warp`，出现支墩和凹龛），太陡的地方先崩塌（`talus`）。岩拱、石林这些岩石道具用同一张表。侵蚀里陡坡上只有“软弱带”冲得出沟，细沟再抹掉，避免满山窗帘褶。
- **山影**（`src/render/sunMap.ts`）：加载地图时沿太阳方向扫一遍高度场，得到每个位置头顶上“被山挡住的光线到了多高”，存成一张半精度贴图。方向光的颜色节点乘上它，所以地面、水面、树、建筑、座舱和体积雾都有山的影子，而且是三维的（飞到影子上面就回到阳光里）。分层阴影的最远一层不再画地形：那一层里只有镜头附近的地形块投影，影子落到远处山坡上是一条条直线。背阴的地形按“对面晒着太阳的岩壁把光反射过来”加一点暖色的自发光（`terrainShader.ts` 末尾），峡谷的清晨黄昏靠它。
- **人眼适应**（`src/render/eyeAdapt.ts`）：把色调映射之前的画面缩成 64 格，异步读回各格亮度（不让 CPU 等 GPU），按中央权重算平均亮度，曝光按时间常数靠向目标（变亮 2.6 秒、变暗 1.1 秒）。只补偿一部分，黄昏还是黄昏；转头看后舱时画面慢慢提亮。
- **水面倒影**（`src/render/mirror.ts`）：沿反射方向走三段。先在屏幕上步进 17 步 + 二分 3 次，碰到画面里的东西就取那里的颜色；飞出画面的光线接着在**倒影场**（`src/render/reflectMap.ts`：地形 + 树冠的高度图和俯视颜色图，打光在着色器里算）里走 20 步，所以山在画面外时水里还是映得出来；什么都没碰到就是天空，按方向算大气颜色（`SkyDome.reflectedSky`），再盖上云层贴图里的云。天空不从画面里取：座舱立柱、山挡住的方向一样有天。远处的倒影按“比像素还细的波”上下拉开（三点采样 + 每像素抖动）。海面和河面共用，低画质关闭。
- **太阳碎金**（`water.ts` 的 `WaterLighting`）：水面的方向光高光换成统计模型：算出把太阳反射进眼睛的小波面要多大坡度，和画得出来的波浪比，比像素还细的部分按 Cox-Munk 的坡度分布算概率。近处是一粒粒闪光，远处自然连成一条光带；`lightColor` 里已经乘过各种影子，影子里没有碎金。月光走同一条路。
- **岩壁细节**：岩石浮雕图（`tools/prep_relief.py`）不是程序噪声，是把真实悬崖（Poly Haven `cliff_side`）的法线积分成高度，放大到 19 / 71 / 230 米三个尺度；三平面投影时 v 轴取“地层坐标”（高度 + 地层面偏移），岩层跟着地层表倾斜、起伏，贴图的上下也摆正了。A 通道是凹处，裂缝和岩层下沿压暗；再加一层顺岩壁流下来的水痕。
- **水系**（`src/world/flow.ts`）：优先填洼后累加集水面积（半分辨率），存进森林图的 G 通道（地形着色器的贴图数已到 WebGPU 默认上限 16）。荒漠里沟是一条条浅色的干河道（`biome.wash`），别处沟里植被更密更绿；植被规则的 `wash` 让灌木沿沟生长。
- **河流**（`src/world/river.ts`、`src/render/riverView.ts`）：地图的 `rivers` 给出沿下游方向的点（水面高度、半宽），`riverLine` 沿谷底中心线蜿蜒并绕开停机坪。地形挖出河床、把两岸修到水面高度；水面是一条带子，两边埋在河岸下面。急流处按坡度起白沫。不参与飞行模拟。
- **旋翼下洗**（`src/render/downwash.ts`，水面部分在 `water.ts`）：桨毂离地面约 26 m 以内开始起效，水面上是一圈向外跑的碎浪和白沫，加上一圈水雾；陆地上是尘土（水泥坪几乎没有），积雪线以上是雪沫。只影响画面。
- **草丛**（`src/render/groundCover.ts`）：贴地 75 m 以内在镜头周围铺草丛（16 m 一块，环形缓冲区，只上传变化的部分）；颜色用和地形草地层相同的噪声与配色，远处淡出。飞高了整组隐藏。
- **窗灯**（`src/render/wetness.ts` 的 `windowGlow`）：黄昏全开、清晨和阴雨天亮一部分，按世界坐标约 2.6 米一格抽签，大约一半的窗户亮着。建筑模型里“又暗又光滑”的纯色部件和程序建筑的玻璃都算窗。
- **石块**（`boulder`）：走树木的实例化和 LOD，不参与碰撞，撒在崖脚、岩架、冰碛和岬角下；颜色是地图的岩石色去一半饱和度。
- **锐化**（`post.ts` 的 `sharpen`）：时间抗锯齿之后一道受限的反锐化，结果限制在周围五个像素的明暗范围内，不产生白边。
- **低云层**：开体积雾时在 `volumetricFog.ts` 里沿视线与云层相交的一段积分（按场景深度截断，云贴着山坡自然消失）；低画质或关掉体积雾时退回 `CloudLayer` 的半透明面片。
- **飞行中的流畅度**：`render/instancing.ts` 让实例网格不走 three.js 的“上一帧矩阵”（否则每帧复制整张矩阵表，矩阵一变还要整块重传；树、石块、建筑本来就不动，上一帧位置直接取当前位置）。`treeView.ts` 的列表是增量维护的：每棵树记着自己在哪一级、哪个槽位，刷新时只改换了细节级或进出视野的树，一帧最多挪 2000 棵远处的树，其余排到后面几帧。整张列表重写一次要传几 MB，传输队列一满，后面几十字节的写入也要排队。
- **地平线**：`FOG.ring` 是地平线一圈 7 个颜色（`SkyDome` 按穹顶同样的公式算），雾、远云都融进视线方向的这圈颜色，远景后面正好就是这个天色；`water.ts` 里像素覆盖范围带来的坡度方差要封顶，否则几十公里外的海面朝哪个方向都反光。
- **任务烟幕**（`render/smokePlume.ts`）：一次实例绘制的烟团，同一时刻放出的摆动同相，连起来是烟柱；按半球法线受光，用场景深度做软边，镜头靠近时淡出。水面、河流、烟幕共用一份场景深度拷贝。
- **飞行界面**：默认“自动”：平稳飞行 6 秒后面板和按键提示都收起，只留没有底色的航向带和下一个航点；有告警、分岔、着陆、任务变化、低速时回来。按 U 切换 自动 / 完整 / 隐藏。
- **飞行训练**（`src/game/tutorial.ts`）：`LESSONS` 里 7 课 26 步，每步写清楚做什么、为什么、放大显示哪些键、看 HUD 的哪里；`check` 读真实飞行状态，`stuck` 是卡住 14 秒后的针对性提示。没学到的操作在 `filter` 里置零，HUD 用 `Hud.setTutorial` 只露出学到的部分。`anchor` 步骤开始时存一个不打扰的检查点，撞了回到这里、耐久补满。可以从任何一课开始（`Lesson.place` 把飞机放好）。
- **休闲飞行**（`RunConfig.free`、`GameSession.free`）：没有任务、补给、检查点和导航，磕碰慢慢恢复，撞毁就回到上空。起点是第一个观景点（`MapDef.vistas`）。暂停菜单换时段、天气、景点（进出夜晚要多一盏着陆灯，所有材质重新编译，所以等 `warmUp`）。`src/sim/cruise.ts` 的自动巡航只通过操纵输入飞，看前方 720 m 的地形，前面有山就减速先爬。电影镜头（`CameraRig` 的 `cinema` 模式）在飞越、伴飞、高空之间切，被山挡住就换下一个。
- **第一印象**：训练场是主菜单的背景，也是第一个看到的世界，按正式地图的标准做（`src/maps/training.ts`、`src/world/props/training.ts`、`tools/blender/props_training.py`）。菜单先放 `public/ui/map_training_bg.webp`，`App.warmMenu` 在后台并行编译，好了再淡入实时画面。`public/ui/` 的图都是游戏里拍的（960×400 卡片、1280×720 加载背景）。
- **并行编译**：`WorldView.parallelCompile` 在预热期间让新建的管线走异步接口（同步接口在显卡进程里只能排队），没编译好的物体先不画；生成世界之前 `WorldView.prefetch` 先把模型和贴图下载起来。
- **着色器编译**：WebGPU 的渲染管线第一次用到时才编译（地形着色器 140 KB，一次要好几秒），所以 `App.warmUp` 在加载界面里让 `WorldView.setWarm` 把场景所有物体都画一遍（隐藏的也画、不做视锥剔除），等帧时间稳定后才进入“点击开始”。环境贴图重烘时写回同一张贴图，否则所有材质都要重新编译。地形颜色不放在 `colorNode` 上：three.js 会把 `colorNode.a` 带进阴影通道的着色器。
- **座舱与直升机**：驾驶舱对照 H125 实机照片建模（`tools/blender/cockpit.py`，烘焙环境光遮蔽），指针按仪表读数转动，发动机/地图/姿态屏为实时绘制的画布贴图；外观（机身、旋翼、尾梁、滑橇）由 `heli_ext.py` 生成，旋翼按转速变成半透明的桨盘。
- **渲染器**：three.js WebGPURenderer（不支持 WebGPU 时自动退回其 WebGL2 后端；`?backend=webgl` 可强制），反向深度缓冲；所有自定义着色都用 TSL 节点写成（地形、水、天空、树、道具细节、座舱玻璃、天气），同一份代码可编译成 WGSL 或 GLSL。
- **后期处理**（`src/render/post.ts`）：低画质 = FXAA；中及以上 = 多渲染目标（颜色、法线、运动向量）→ GTAO 环境光遮蔽 → TRAA 时间抗锯齿 → [泛光] → Khronos PBR Neutral 色调映射 → 显示空间调色（S 曲线、自然饱和度、分离色调、暗角）；可选按运动向量的动态模糊。离镜头 2.5 m 以内（座舱内部）不叠加屏幕空间遮蔽（座舱模型已烘焙遮蔽）。
- **体积雾与丁达尔效应**（`src/render/volumetricFog.ts`，中及以上画质，设置里可关）：在 GTAO / SSGI 之后、TRAA 之前叠加。约半个屏幕分辨率沿每个像素的视线步进：近处（≤ 0.8–1.5 km，平方分布、密在近处）累加贴地薄雾（按地表高度图的离地高度衰减，林区更浓，三维噪声的团块随风飘动）与低空霾，每个采样点用 CSM 第 2~4 层阴影贴图判断阳光是否被挡住、再乘云影；Henyey-Greenstein 前向散射（g ≈ 0.72~0.76）让迎着太阳时光束最亮。远处（到 8 km）只统计视线上被遮挡的比例，按解析雾的权重把雾里朝太阳一侧的散射扣掉（山影、云隙光），不重复加雾。结果按深度升采样（四邻深度相近时双线性，否则取最接近的那个，避免树叶边缘的光晕）后合成：颜色 × 透过率 + 散射光。步进起点每帧抖动，由 TRAA 累积降噪。
- **夜晚**：太阳换成月亮（同一盏方向光，阴影、山影、水面的月光都照常工作）。`SkyDome.setNight` 把天光压到月夜的亮度（`NIGHT_TINT`），加星星（按方向分格抽签）、银河和月面；云按月光照亮。人眼适应的上限放宽到 3.6。座舱：表盘刻度和面板字样从里面亮起来（`CABIN_NIGHT`，贴图亮的部分自发光），屏幕调暗（屏幕也过曝光，要除回来）。机头着陆灯是一盏聚光灯（只在夜晚放进场景，多一盏灯所有材质都要重新编译）；路灯、高杆灯、停机坪边灯在 `nightLights.ts` 里是两次实例化绘制的加法面片。
- **雨刷**（`cockpit.ts`）：转轴用射线落到风挡上，臂和刮片绕玻璃法线转，雨大开快档；刮过的扇形里水膜很薄。停着时收在风挡下沿外面。
- **风挡倒影**（`cockpit.ts`）：反射光线落在遮光罩这个已知的平面上，到画面里取那一点的颜色，一次采样；按菲涅尔叠加，玻璃是 alpha 混合，发光项要除以 alpha。
- **分层阴影隔帧更新**（`sunShadows.ts`）：阴影占一帧绘制调用的一半以上，CPU 是瓶颈。最近一层每帧画，往外隔 2、4、8 帧，错开在不同的帧里；相机转过一定角度或走出一段距离就立刻重画。
- **时段**（`src/render/timeOfDay.ts`，简报里选择，只影响画面）：清晨 / 黄昏把太阳放到 6~8° 高（地图可用 `sunDawn` / `sunDusk` 自定）；天空亮度标定、阳光强度、环境光随太阳高度（`SkyDome.dayK`）变暗，阳光颜色由大气透射算出（自然变成橙红），曝光只补回一部分；清晨的贴地薄雾约 3 倍、更厚，清晨与黄昏的低空霾 1.7 倍；CSM 的 `lightMargin` 随太阳高度加大，远山的长影能投进谷里。
- **雨天湿润**（`src/render/wetness.ts`）：建筑模型（顶点色材质与贴图材质，加载时换成节点材质）、程序道具材质按天气的 wetness 变深（× 0.7）、粗糙度趋向 0.12；朝上的面湿得最透，竖直墙面约三成，檐下几乎不湿。地形有自己的一套。
- **座舱玻璃**：除了雨滴与雨痕，还有一层灰尘与擦拭痕（两层噪声），平时几乎看不见，视线接近太阳方向时按 cos¹⁰ 发出眩光。
- **云影**（`src/render/cloudShadowMap.ts`）：每帧把头顶云层沿太阳方向的透过率画进一张 512² 贴图（覆盖相机周围 16 km，按纹素对齐），所有受光材质（太阳光的颜色节点）和体积雾查同一张图；云的密度与天空里的体积云是同一个函数，所以云影的位置、形状跟看到的云一致。只在开启体积云（高、极高）时有效。
- **光线追踪开关**：浏览器没有硬件光线追踪接口（WebGPU 标准里没有），但这个世界的主体是一张高度图，光线在高度图里走就是真的光线追踪，看得到画面外的山。开关只在不开时的画面上加东西，水面倒影、体积雾、GTAO 一层都不换。`src/render/giField.ts`：进图时在显卡上给地图每一格（512×512）放一个探针，各发 128 条光线（斐波那契球面，所有探针共用一组方向，所以没有噪点），碰到地面按颜色、朝向、山影算反上来的光，碰到水面算反射的天光和碎金，走三轮就是三次反弹，结果存成一阶球谐（平均亮度 + 从哪边来）。太阳在一局里不动，所以只算一次（约 30 ms），飞行时每像素只多三次纹理读取。后期按像素的世界坐标和法线取值，乘上 G-buffer 的反照率。金属、玻璃沿镜面方向走同样的光线，映出地形和水面。舱内补光读探针图在内存里的一份，跟着脚下的地面变化。试过 three 的 SSGI / SSR / SSS，都不合适：SSGI 把天空也当成光源，阴影全被冲灰，平均亮度高 10~30 级；SSR 在屋檐和门板边上是一排锯齿；SSS 在白色机身上是一片噪点；而且当时开关一开就把水面的三段倒影关掉了。
- **透明物体与辅助通道**：法线、漫反射、运动向量通道设成“跟随材质混合”，透明材质（玻璃、光柱、雨、云）写 alpha = 0 的值即保持后面不透明物体的数据（WebGPU 后端按渲染通道上的设置决定逐通道混合）；水面改为不透明 + 最后绘制，用折射采样代替半透明。
- **阴影分层与图层**：CSMShadowNode 四层（4 / 40 / 320 / 2600 m）。图层 1 = 只在远处的物体（中景 / 远景模型、较粗的地形块），图层 2 = 能进最近两层阴影的物体（座舱内部只在图层 2）；最近两层只画图层 2、外面两层画图层 0 和 1，避免把远处物体逐层提交（CPU 绘制开销是这一代渲染器的主要瓶颈）。
- **其他**：分块地形 LOD 与裙边、视锥剔除、雨线与云层、闪电。
- **画质档位**（低 / 中 / 高 / 极高）只影响渲染（分辨率、阴影距离与精度、树木与建筑的细节距离、地形细节与照片材质、抗锯齿、环境光遮蔽、泛光、体积云步数、雨密度），**不影响物理和碰撞**；光线追踪是独立开关。首次启动按显卡选择（WebGL2 后端按驱动报告的型号、WebGPU 后端按厂商与架构）：集成显卡选低画质并在主菜单提示切换到独立显卡。
- **舒适性**：视野、镜头抖动、头部晃动可调；动态模糊默认关闭；闪电可关闭。

### 反扭矩（`src/sim/flight.ts` 的 updateSim）

超仿真里机身要受主旋翼的反扭矩 `qMain = 轴功率 / 旋翼角速度`，方向把机头往右推。悬停大约 6900 牛米，总距联动（`simPedalMix`，真机的总距-偏航补偿）在脚蹬中立时顶回去约 5100，所以中立脚蹬下还差约 1800 牛米，关掉增稳后机头每秒往右转 35~45 度，大约要 10% 的左脚蹬才能顶住。这个比例是真实飞机的做法：巡航时脚蹬接近中立，悬停和爬升要左脚。增稳开着时偏航阻尼器把 `qMain` 整个补掉，所以开着不转。

键盘飞脚蹬有两个问题，都在这里解决：

- **只有按和不按**：10% 的脚蹬在满行程上只是 0.1 秒的事。`pedHold` 让刚按下时走得慢（每秒 40%），按久了才快；总距的 `colHold` 同理，点一下是微调，按住才是用力提。
- **松手回中**：真机的脚蹬没有回中弹簧。增稳关着时 `trimPedal` 跟着 `ped` 走，踩到哪里留在哪里；增稳开着时脚蹬要的是转弯速度，松手回中。

滑橇的摩擦（`src/sim/gear.ts`）以前只按速度算，任何持续的力都能推着飞机慢慢走：旋翼一转，机头在地上每秒蹭 0.6 度。现在慢到 0.15 m/s 以下就“粘”在地面的一个点上，力由偏离这一点多远来算。

### 超仿真教学（`src/game/simTutorial.ts`）

和基础教学共用 `Tutorial` 类，课表换成 `SIM_LESSONS`。多出来的东西：`control`（这一步要点的控件，外面亮一圈，不在视野里时告诉玩家往哪边看）、`live`（HUD 收起来了，要看的数字写在卡片上）、`quick`（自转时分秒必争，完成了不停下来打勾）、`Lesson.jump`（学完上一课接着学时也回到这一课的起点）、`Lesson.park`（停在坪上，发动机已经在转）。`tests/sim-tutorial.test.ts` 里有一个只会按键的学生，每一帧走真实的物理把课程学一遍。

### 超大地图和救援模式（`src/sim/rescue.ts`、`src/maps/grandcanyon.ts`、`src/ui/rescuePanel.ts`）

**超大地图**：`MapDef.flightSize` 比 `size` 大。核心区还是 `size`（物理和细节都在这里），`Heightfield.outer` 接中圈的 20 米高程，`heightAt` 出了核心区自动查外面一层，所有用地面高度的地方不用改。物理上多加一张 Rapier 高度场，核心区那一块压到地下（`sunkenCore`），两层不打架。边界墙在 `flightSize/2`。GPS 的地图也按这个范围画。

**坪**：`style: 'field'` 是野外的降落点：看不见的落地面（起落架的射线打在它上面才算落在坪上）、四角橙色布板、担架和人。高度写 0 的坪在 `worldgen.settlePad` 里取当地的平均高度；核心区外面的坪压的是中圈的网格（`flattenGrid`），物理和画面是同一份数据。`outerForest` 在外圈的降落点周围种树：外圈影像只有 10 米一个像素，认不出树，飞到跟前不能是一片光地。

**任务**：`MapDef.rescues` 写一站一站的停靠点，`rescueMission` 变成普通的任务目标（`land`、`hover`），所以导航、检查点、失败恢复、自动驾驶全都不用改。吊运是 `hover` 加 `cargo: 'hoist'`。没有航线时导航直飞目标，`Navigator` 到 320 米以内算进近。`GameSession.create` 的第五个参数是这一趟的定义，出生点和任务都从它来。

**伤员**：`RescueRuntime.health` 从 100 往下走，黄金时间（`golden`）用完正好见底。机上有人时颠簸加速掉血，硬着陆直接扣。掉到 0 不算失败。送到时记下状况，下一个人从满状态开始，所有人的平均值进评分（顶替可选任务那一栏）。

**验收**：`tools/rescue.tool.ts` 读真实地形数据，自动驾驶用和玩家一样的操纵输入把四趟全部飞完，要求 0 碰撞。

### 真实地形（`src/render/realTerrain.ts`、`src/world/realData.ts`、`tools/real/`）

大峡谷是第一张用测绘数据的地图，走一条和程序生成地图并行的路：`MapDef.real` 有值时，`generateWorld` 读高程而不是算高程，`WorldView` 建 `RealTerrain` 而不是 `TerrainView`。

- **三层嵌套**：核心 10.24 km（2.5 米一格，物理、碰撞、飞行都在这里）、中圈 41 km（20 米）、远圈 164 km（160 米，只看不飞）。外面两层把地球曲率烘进了高度。
- **网格**：CDLOD。一块 64×64 的网格实例化绘制，四叉树按距离选块，顶点着色器用 `textureLoad` 取高度，快换级时奇数顶点滑向粗一级的位置，裙边遮缝。最细一级和 Rapier 高度场的三角剖分一致。
- **从照片到反照率**（`prep_grandcanyon.py`）：航拍里有拍摄时的太阳。除掉坡面明暗；影子里的颜色已经丢了，按岩层高度借晒着太阳的同一层岩石的颜色。算出来的影子只当候选范围，真正够暗的才算影子，因为这片影像是两天拍的。
- **崖壁**：航拍是从正上方拍的，接近竖直的面只有一条缝。七十度以上的面改查岩层色表（`strata.png`，4096 像素，0.44 米一格，细的层理也写在里面，远处靠 mipmap 平均掉），明暗取照片的低频，再加雨水痕迹。地层不是水平的：让崖壁的高度分布最集中，拟合出往北每公里抬升约 16 米（`dip`）。
- **辅助图**（`sky_river.webp`，5 米一格，无损）：R 岩缝，G 河面，B 看得到的天空（16 个方向找地平线，余弦加权，看到两公里外）。天空可见度进 `aoNode`，峡谷深处才暗得下去。河面来自激光测绘的压平水面：谷底又平又连成一片的地方。
- **山影**：`sunMap` 一张贴图的左右两半分别是核心区（5 米）和中圈（20 米），不多占采样器。
- **树**（`trees.dat`）：航拍上周围亮、中间暗的斑点。南缘是矮松和刺柏，溪边是三角叶杨，其余是灌木。位置是真的，大小和种类按高度估计。
- **采样器上限**：片元着色器 16 张贴图。层与层之间的过渡烘进影像（`blend_edge`），天空、河面、岩缝合成一张，都是为了省采样器。
- **文件名**：`.bin`、`.gz` 这类后缀会被下载软件（比如 IDM）拦走，网页只收到一个空的 204；`aux`、`con` 这些是 Windows 的保留设备名，Git 打不开。见 `tests/real-data.test.ts`。高程用 `.dem`，树用 `.dat`。文件是 gzip 压缩的，有的服务器会替浏览器解开，所以读的时候看文件头。

## 10. 存档与兼容性

- 本地存档带版本号（`rotorTrails.save`，当前 v4；v1→v2 把仍是旧默认值的“下降 = Ctrl/X、视角回正 = C”改成“下降 = C、视角回正 = Z”，v3→v4 再把“下降 = C、动力增强 = Shift”互换，玩家改过的键位不动），逐项校验并夹取范围；JSON 损坏时回退默认值并把原数据备份到 `rotorTrails.save.corrupt`；存储不可用（隐私模式等）时提示“进度不会被保存”，游戏照常运行。
- 启动时检查 WebGL2 与 WebAssembly，不支持时显示原因和解决办法，而不是黑屏；脚本下载期间显示加载画面。
- 鼠标观察优先使用指针锁定（需要用户点击）；浏览器拒绝时退回“按住左键拖动”。
- 浏览器快捷键冲突：Ctrl+W 等无法被网页拦截（按住 W 再按 Ctrl 会关闭页面），所以默认键位不用任何修饰键：爬升 = 空格、下降 = Shift（Shift 不是浏览器快捷键的一部分，按住 W 再按 Shift 没事）；飞行中关闭页面前弹出确认；窗口失焦时清空按键状态。
