# Rotor Trails：设备适配与品质审计

日期：2026-11-12（日本时间）。范围：本地仓库当前代码；保留飞行物理、任务规则、地图内容、辅助档位与基本操作方式。

> 后续打磨：完整飞行备份、导入保护、舒适显示、加载取消与读档精确恢复已继续实现；最新结果见 [品质打磨与验收报告](quality-polish-2026-11-12.md)。下方测试数字保留本阶段的历史记录。

## 结论与边界

游戏为 TypeScript + Three.js + Rapier 的纯前端静态应用，没有独立服务端。此次“底层修复”覆盖输入、渲染生命周期、存档和响应式界面。本轮修改保存在本地工作区，尚未发布到线上。源码检查和自动化不能替代 iPhone / iPad / Android / macOS Safari / Linux / 实体手柄的实际游玩，也不能据此承诺年度奖项。

## 已确认并处理的问题

| 优先级 | 问题与触发条件 | 修复 | 验证 |
| --- | --- | --- | --- |
| P0 | GPU 连接丢失后仅关闭输入，游戏状态仍为 playing，帧循环继续；只保存总进度，没有保存本次飞行 | 冻结飞行和渲染回调；在独立自动存档槽保存有效飞行；阻止再次起飞；恢复提示反映实际保存结果 | app-lifecycle：保存成功、存储失败、重复 GPU 回调、停止帧循环 |
| P0 | 手机上飞行时转竖屏，CSS 提示遮挡画面，物理仍继续 | 自动暂停、释放触控输入；回到横屏不自动恢复；菜单与设置允许竖屏访问 | app-lifecycle：旋转暂停与主动恢复 |
| P1 | 只有 visibilitychange / beforeunload 的离开保护，没有 pagehide 兜底 | pagehide 同步保存设置、结果和有效飞行，暂停并清空输入 | app-lifecycle：不触发其他离开事件时仍保存 |
| P1 | 一帧运行异常后立即销毁，当前有效飞行未尽力保存 | 销毁前尝试保存飞行和总进度；保存失败仍终止异常循环 | 生命周期异常测试 |
| P1 | 飞行存档读取失败、JSON 损坏或来自未来版本时，会被当作空槽位集合，后续写入可能覆盖原数据 | 不可读期间拒绝写入并保留原始数据；后续成功读取后恢复保存 | flight-save：读取失败后恢复、损坏 JSON、未来格式、非法槽位容器 |
| P1 | 触控指针捕获丢失、失焦、切换模式时，摇杆和视线可能残留输入 | 统一 reset；捕获丢失时释放摇杆；切换设备、失焦与销毁时清空 | Input 单元测试 + 实际 DOM 指针捕获回归 + 浏览器触控飞行 |
| P1 | 二合一设备同时具有触屏和鼠标，旧检测可能关闭触控；触过屏幕后无法再正常使用鼠标锁定 | 首次手指操作启用触控，键鼠／手柄操作切换提示并隐藏触控；主动退出鼠标锁定不误暂停；窄竖屏切入触控时仍暂停 | 混合输入浏览器脚本 + Input / App 生命周期测试 |
| P2 | 小尺寸触屏的语言、分页、设置控件点击区域偏小；横屏菜单顶部拥挤 | 触屏主要按钮、分页、下拉框与滑条目标至少 44 CSS px 高；窄屏语言切换进入正常布局；保留页面滚动 | 667 × 375、320 × 568 浏览器尺寸与截图检查 |
| P1 | 触控层未由 App.dispose 释放，重新构建实例可能残留 DOM / 后续监听 | 显式销毁触控层、清除触控样式和名称模式 | 生命周期与输入测试 |
| P2 | 首次触摸进入全屏与继续飞行使用不同代码路径，部分浏览器 API 缺失或同步抛错处理不一致 | 统一入口，安全检查屏幕方向锁定 API，失败时保留普通窗口游玩 | 类型检查与相关生命周期测试 |

## 下一阶段的品质优先级

1. **首次游玩与教学可理解性。** 建议招募至少 5 名没接触过本作的玩家，覆盖中文、英语和日语；记录进入训练、完成起飞、理解目标与第一次安全着陆的时间和失败原因。先验证现有教学，依据反馈修文案和信息层级，保持物理与玩法。
2. **真机性能预算。** 建议桌面目标为稳定 60 FPS、主流手机最低目标为稳定 30 FPS；记录平均帧率、慢帧、内存以及连续 20 分钟后的热降频。目标值尚非本轮实测成绩。优先考察首次载入、切换地图、暴雨／浓雾和大峡谷。
3. **加载成本。** 当前 public 素材合计约 146.28 MB，其中大峡谷的影像与高程占主要部分；这是全部资源体积，不是首屏下载量。首屏还需要物理引擎、渲染器和部分模型。建议分别测冷缓存与热缓存首个可操作画面的时间，之后再决定分包、流式加载或压缩，避免为了减少体积损坏画质。
4. **视听一致性与信息反馈。** 由真人用耳机和普通扬声器检查旋翼、告警、音乐的相对响度；检查重要任务反馈在晴天、夜间和暴雨下是否都易读。长时间飞行需关注眩晕、镜头运动与疲劳。
5. **内容记忆点与呈现。** 保留五张任务地图的结构，优先加强现有关卡的目标解释、抵达反馈、地标辨识与通关收尾。用真实游戏画面制作多语言短预告，并观察玩家是否能在 30 秒内说清游戏的独特吸引力。
6. **跨设备存档完整性：后续已实现。** 完整备份已包含手动／自动飞行、设置与进度，支持预览和旧版导入；原子写入、失败保留、旧标签页保护及空中读档演练详见后续报告。浏览器内恢复已验证，跨操作系统／跨浏览器文件交换仍需真机验收。
7. **可读性与单位。** 当前没有独立 UI 缩放设置，高 DPI 桌面依赖浏览器缩放；高度仍只有米。前者值得优先验证 HUD 与驾驶舱在 4K 屏上的可读性，后者可按受众补充英尺。两者都不需要调整物理规则。
8. **发布门槛。** 在现有单元与全路线回归之外，固定保留跨浏览器真机清单、至少一轮长时间游玩和一次存档导出／导入演练。未验证的项目保持明确状态；不使用“全设备完美兼容”作为发布结论。

## 浏览器行为参考

- [MDN：pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event)：补充页面历史切换保护，但移动系统强制终止仍不保证触发生命周期事件。
- [MDN：beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)：不能单独依赖其保护移动端存档。
- [MDN：ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)：方向锁定存在兼容性与全屏等前提；失败必须安全降级。
