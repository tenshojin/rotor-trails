# Rotor Trails：品质打磨与验收报告

日期：2026-11-12（日本时间）。承接 [设备适配审计](compatibility-audit-2026-11-12.md)。

> 复核（同日）：这两轮的改动经过逐文件复核和真实浏览器重走后才提交。复核改了几处：手机点按后浏览器补发的鼠标事件不再被当成“换成鼠标”；带触屏的电脑碰屏幕不再改辅助、不再全屏；飞行存档有一格读不懂、或整份坏了时不再永久只读（读不懂的原样保留，坏了先备份再继续；更新版本的仍不覆盖）；飞行状态有 NaN 时不写；横屏手机的休闲暂停菜单把“继续飞行”放到标题下；提示文字改成全游戏一致的说法。下文“不可读期间拒绝写入”“35 / 35”等是本报告当时的状态，最新结果见 [测试报告 0zr](test-report.md)。

## 当前结论

本轮已继续修改本地代码，重点解决存档可信度、恢复精度、显示舒适度与加载取消。核心飞行动力学、任务结构、评分规则和基本操作保持原样。项目是纯前端静态游戏，底层改动发生在浏览器运行、存储和资源加载层。本轮没有推送、部署或更新线上版本。

当前完成的是可验证的技术打磨。年度级完成度还需要新玩家试玩、真实设备性能与长时间视听体验的证据；这些不能从单元测试数量推导出来。

## 本轮发现并修复的问题

| 问题 | 现在的行为 | 验证重点 |
| --- | --- | --- |
| 备份只带走设置和总进度，半途飞行留在原浏览器 | 完整备份包含手动／自动飞行、检查点、设置与总进度；导入显示日期、通关地图数、飞行数量和替换范围 | 完整容器重开、后续保存、旧备份兼容 |
| 主进度和飞行槽位分别写入，会有半份导入的风险 | v5 完整导入用一次 localStorage 写入提交；写入失败时原数据和内存保持不变 | 模拟容量不足、读取禁止、重试、空槽位 |
| 导入后旧实例或另一标签页可能写回旧进度 | 成功导入停止旧实例和待保存定时器；导入代次变化阻止旧标签页写回，并要求刷新 | 刷新失败／被阻止、跨标签页、离开事件 |
| 深层存档损坏可能在恢复中途抛错 | 导入和恢复前检查机体、任务、导航、天气、补给和每个检查点；损坏数据拒绝恢复，现有局面不发生部分改变 | 空数组、错误类型、非有限数值、零四元数、未来格式 |
| 文件读取先后顺序可能与用户选择顺序相反 | 新选择、取消、换页签、关闭设置都会使旧读取失效；超过 10 MB 的文件在读取前拒绝 | 异步读取竞态与大小边界 |
| 导出成功提示过于肯定，不能区分部分备份和当前航程未写入 | 区分完整备份、仅进度、仅已有存档和下载未启动；提醒确认文件已落到设备上 | 存档不可读、当前飞行保存失败、下载 API 失败 |
| 舒适相关选项分散 | “画面 → 舒适显示”一次关闭镜头震动、头部晃动、动态模糊和闪电闪光；仍可逐项调整 | 只改四个效果字段，保留操纵、其他画质和焦点 |
| 地形预取并发不受控，中断后还可能继续下载或覆盖恢复页面 | 预取去重、最多四个并发；销毁或 GPU 中断时取消；过期进度不再更新 UI | 取消后的队列、进度回调、HTTP 失败、重复文件 |
| 读档后尚未按“开始”就移动和回血 | 去掉恢复后的额外物理步；单独查询离地高度并刷新运动仪表读数 | 时间、位置、速度、耐久、检查点不变；下一物理帧一致 |

最后一项是在浏览器演练中发现的真实差异：原来恢复后多走 1/60 秒，飞机移动约 0.145 m，休闲模式耐久从 64 提前回到约 64.067。修复后恢复时间完全相等，位置和速度误差均为 0，耐久保持 64，等待玩家点击开始。

## 存档兼容性约定

- v5 完整文件：替换进度、设置和全部飞行槽位。零份飞行意味着明确清空槽位；确认界面会显示这一点。
- 旧版／仅进度文件：更新进度和设置，保留本机飞行槽位。
- 不可读的飞行集合不会被导出成“空的完整备份”，避免导入时误删目标设备原有飞行。
- 未来版本或损坏数据不会被静默降级或覆盖。
- v1–v4 的独立飞行存储保持兼容；完整导入后以单键内嵌容器为准，旧独立键不参与读取，也不会在删除新槽位后复活。
- 容量不足会保留原数据并报告失败。此方案是手动文件迁移，不是云同步，也不解决两个正常游玩标签页同时修改总进度的所有冲突。

## 验证记录

- 全部单元与集成测试：**90 个文件，671 / 671 通过**。
- 全航线／天气回归：**46 / 46 通过**；六张地图的两种恢复场景：**12 / 12 通过**。
- TypeScript 类型检查、生产构建、差异空白检查通过。
- 五种尺寸的 DOM 回归：**每种 35 / 35，共 175 项通过**；最终各组控制台均无错误。
- 相比本阶段开始时的 650 项，新增 21 项测试；此前阶段的 637 → 650 项记录保留在设备审计报告中。

五种界面尺寸为 1280 × 600、320 × 568、568 × 320、1024 × 768、3440 × 1440。每种执行 35 项真实 DOM 检查，覆盖设置、确认界面、触控捕获、舒适设置、导出状态和异步文件选择。

浏览器飞行演练使用 Windows Chromium、隔离配置和软件 WebGL，模拟 844 × 390 触屏视口：

1. 等待着色器预热结束，出现可点击的开始按钮。
2. 在实际会话中通过测试接口设置空中位置、前向速度、耐久 64 和命名检查点。
3. 从实际存档实现生成备份文本，通过文件选择事件导入。
4. 刷新后使用主菜单“继续飞行”，再次等待真正的开始界面。
5. 核对时间、位置、速度、耐久与检查点；核对舒适设置四项效果关闭且游戏保持暂停。

最终严格演练：位置误差 **0 m**，速度误差 **0 m/s**，时间相等，耐久 **64**，检查点正确，控制台错误 **0**。恢复界面显示约 31 km/h、离水面约 80 m，与恢复状态相符。

这些不是人工驾驶成绩，也不是移动设备帧率测试。场景通过测试接口构造，设置页截图阶段暂停了软件渲染帧循环，以避免软件 GPU 妨碍 DOM 绘制。实际保存文件到操作系统下载目录、跨操作系统文件交换、Safari、真实触控／手柄和真实 GPU 中断仍需对应设备验证。

## 距离年度级完成度，仍未闭环的事项

以下是明确的待验收项；没有证据证明已经达标，也不把它们都称作已确认缺陷。

| 优先级 | 当前不足／证据缺口 | 具体完成标准 |
| --- | --- | --- |
| P0 | 尚无覆盖目标设备的持续游玩证据 | Windows 独显与核显、macOS Safari、Linux Firefox、iPhone Safari、Android Chrome、平板各完成进入游戏 → 飞行 → 暂停 → 后台 → 回来 → 存读档；真机完成多指触控、旋转、手柄断线与重连 |
| P0 | 首次上手与失败反馈缺少陌生玩家验证 | 至少 5 位新玩家，无口头指导；建议至少 4 位在 10 分钟内学会起飞、转向、悬停与暂停。记录首次落地失败原因；玩家应能说出下一次该调整下降速度、漂移、姿态还是位置 |
| P1 | 真实性能预算尚未实测 | 桌面 60 FPS、主流手机 30 FPS 是候选目标；测试晴天／夜间／暴雨、五次地图切换、连续 30 分钟，记录帧时间分布、最长停顿、内存和热降频；按设备确定默认画质 |
| P1 | 冷启动成本仍较高 | 对物理引擎、渲染器、模型和地形分别记录冷／热缓存的下载、生成、编译和首个可操作时刻；用实测选择后续压缩和分阶段加载方案。此次四路预取只约束请求压力，尚未证明缩短启动时间 |
| P1 | 听觉反馈和长时间舒适度尚无真人验收 | 耳机及普通扬声器分别检查旋翼、告警、音乐；三种语言在夜间和暴雨下完成任务。至少 20 分钟舒适显示试玩，记录疲劳与不适；该设置仍保留真实机体运动，不能保证消除眩晕 |
| P1 | 关卡的辨识度和通关后的满足感缺少玩家证据 | 保持现有五张任务地图与路线，观察玩家是否能记住每张图的地标、任务理由和一次关键操作；据此打磨目标说明、抵达反馈和结算呈现 |
| P2 | 4K、小屏与不同语言的可读性仍依赖实机观察 | 验收浏览器缩放、HUD、座舱仪表、长日文／英文、刘海与分屏；根据结果决定独立 UI 缩放。高度单位目前以米为主，是否增加英尺属于后续可选增强 |

建议将上述 P0 与 P1 验收作为上线前检查。发现的可复现程序问题继续修复；涉及美术重做、关卡叙事或玩法方向的选择，再结合试玩证据决定。自动化通过不等同于完整设备认证或奖项就绪。
